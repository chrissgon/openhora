# What stage 4 showed so far (2026-10-06)

Stage 4 of the platform plan (`platform-plan-2026-10-05.md`) takes a code change from a run to a pull request: the project's dependencies installed by code, the change set a run leaves, the project's protected paths checked on it, the pull-request skill run up to its confirmation gate with its payload recovered, and the effect a person approves by its hash and code executes through the code provider. This file records what the reconcile of the stage found in the code, what the measurement of the gate (WP-4.7, Part E) showed, and what waits for the stage's acceptance (WP-4.10), which needs a credential only the maintainer can store.

It holds counts, kinds, endings, durations and token counts only: no content of a run's documents, no person and no identifier. The maintainer was away and had delegated supervision; the decisions below were given by the supervisor on that delegation.

## The measurement of the gate (WP-4.7, Part E)

On a scratch project made from the skill's own fixture, with invented names, one commit and a configuration naming a code host repository and base `main`. Each of three requests on the flow `code-change` ran its implement task, was released, then ran its pull-request task to the gate; then the request was cancelled. No effect was approved, so nothing reached a code host. Fresh requests were used rather than answering the effect, so that each gate run was the first run of its task.

| Run | Skill | Tier | Key | Ending | Pending | Payload recovered | Duration (ms) | Tokens |
|---|---|---|---|---|---|---|---|---|
| 1 | eng-implement | floor | lab | done | review, change set of 3 files, not blocked | | 126,210 | 170,236 |
| 2 | ops-pull-request | floor | lab | gate | effect | yes, parsed, base and head agreed | 49,992 | 160,453 |
| 3 | eng-implement | floor | lab | done | review, 3 files, not blocked | | 38,613 | 158,932 |
| 4 | ops-pull-request | floor | lab | gate | effect | yes, parsed, base and head agreed | 35,976 | 121,224 |
| 5 | eng-implement | floor | lab | done | review, 3 files, not blocked | | 49,863 | 163,414 |
| 6 | ops-pull-request | floor | lab | gate | effect | yes, parsed, base and head agreed | 34,554 | 124,722 |

Every run: `ok` on the first attempt, `skill_loaded` 1, no value replaced in what it left, a use recorded, the image the evidence's; nothing came back as a loose file and the project's working tree stayed clean. Total: 6 runs, 335,208 ms of model time, 898,981 tokens; the three gate runs 120,522 ms and 406,399 tokens.

**The recovery is adopted.** In all three gate runs the reply held exactly one payload line, the file was under the run's returned temporary folder, its hash was the one stated, it parsed, and its base and head were the configuration's. Part F (a runtime mode in the skill, an X change and a full lab test) is not needed. The skill was not edited.

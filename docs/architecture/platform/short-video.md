# A feature across layers: the short video

Part of [the platform map](README.md). This page has the eight sections of a layer page, in the same order, and it is not a layer: it follows one feature (a recording and a script become a vertical video) through the providers, the shared presets and the checks. The layer that holds the code is [providers.md](providers.md).

## Purpose

Two classes make a short video, and both are used by the task runtime alone: no skill requires them (decision VD2 of [the V0 decision](../../decisions/2026-11-07-v0-short-video-hyperframes.md)), so [contracts/environment.md](../../../contracts/environment.md) does not list them. `providers/resolve.py` knows both as roles (`ROLES`).

- **`transcriber:speech`** (`providers/transcriber/whispercpp.py`). Takes an audio or video file, a pinned model name and a language, and writes a transcript, word by word with times (`transcript.schema.json`). It runs whisper.cpp in a container on the person's machine; the audio never leaves it and no model of any provider sees it. It returns counts on stdout, never words.
- **`renderer:video`** (`providers/renderer/ffmpeg.py`, the one engine since PF-b). Takes a recording, a transcript, a post with a script block and a platform file, and returns a 1080x1920 H.264 + AAC video, a cover frame or a still frame of a recording. No model is involved: the edit list is built by code from the transcript, the beats come from the post's script block, a pinned headless browser draws the overlays frame by frame, and ffmpeg cuts and composes. A second engine, HyperFrames (`providers/renderer/hyperframes.py`, V3a to V4), sat behind the same class (VD1) until PF-b retired it (`docs/decisions/2026-11-26-pf-b-retire-hyperframes.md`): `CLASS_DEFAULTS` is `ffmpeg`, the name `hyperframes` is read as `ffmpeg` (`RETIRED` of `providers/resolve.py`), and a project may still name its engine with `media.renderer` in `docs/workbench/runtime.json`.

Everything that reads a recording, a transcript or a post runs inside a container (VD4), through `providers/_container.py`: no network, a read-only root, every capability dropped, no host environment, an image run by the id the build recorded.

## Abstractions

**The common part and the drawing part.** The renderer's modules fall in four kinds, and the kind says what a module may import.

| Kind | Modules |
|---|---|
| Common (no browser, used by every engine) | `_align`, `_edl`, `_media`, `_redact`, `_text`, `_timeline`, `_vocab`, `_layout`, `_assets`, `_output`, `_blocks`, `_hf_page`, `_hf_compose`, `_gsap_lint`, `_payload` |
| Drawing (the ffmpeg engine's own: the browser, the frames, the storyboard) | `_cdp`, `_frames`, `_lint`, `_render`, `_preview`; the host's `_browser` |
| Host (not in the image) | `_docker`, `_image`, `_host`, `ffmpeg.py` |
| Inner (the container's entry point) | `_inner.py`: imports only common modules at the top; `render`, `storyboard` and `selfcheck` import the drawing modules inside their own functions |

What the three newest common modules hold: `_layout` is the arithmetic of where a thing may be drawn (`zones`, `caption_hit`); `_assets` is what is served to a page (`font_allowlist`, `load_fonts`, `load_assets`, `read_regular`); `_output` is how a result is stored (`read_platform`, `make_cover`, `make_still`, `png_size`, `write_once`). An old module imports each moved name back, so a caller and a test still find it where it was. A second engine imports the common modules and `_host.add_common_parsers` and never `_frames`, `_cdp`, `_render` or `_preview`. `_blocks` is the catalogue: the blocks, the engine that may draw each, and the check of a block's parameters.

**The host and the inner side.** The host (`_host.py`, with `_docker.py`) checks the flags, stages the inputs into a private job folder (`Job`), builds the `docker run` command, runs it and reads the result as untrusted, rebuilt from a closed schema. The inner side (`_inner.py`) runs inside the container on `/job` and `/in` (read-only), `/out` (the one writable mount) and `/scratch` (memory-backed). `_host.COMMON_VERBS` names the verbs that need no browser and that every engine serves the same way: `analyse`, `base`, `align`, `check`, `cover`, `still` and `verify`.

**The retired HyperFrames engine (PF-b).** Until PF-b a second engine, `hyperframes.py`, drew the picture in its own image (`hyperframes-image/`) and ran five containers per render: `hf-page`, `proxy`, the HyperFrames drawing container (`hf_render.py` and `hf_measure.mjs`, a ProRes intermediate), `encode` and the verification. It also ran two gates that no flag turned off, the face-region PSNR (advice `face_pixels_changed`) and the glyph-box check of a caption (advice `caption_not_drawn`). All of it is deleted: the class has one engine, which draws with the common image only (the render's drawing pages, one ffmpeg graph and the verification in a fresh common container). The two advice codes keep their place in the closed lists with no producer, so an old task's advice still reads; the engine's own checks (`block_not_drawn` for a card or caption page that draws nothing for six frames or more, the exact pixel gates of every overlay frame) are the ffmpeg engine's. The code is in git history (decision `2026-11-26-pf-b-retire-hyperframes.md`, section "Verified and not verified").

**The image of each provider and its manifest.** The transcriber image is built from `providers/transcriber/Dockerfile` (the base by digest, whisper.cpp by tag and commit), and holds no model. The ffmpeg engine's image is built only from the files `image-manifest.json` lists; the tag is the sha256 of exactly those files (`_image.py`), so an edit to a host-only file (`ffmpeg.py`, `_docker.py`, `_browser.py`, `_host.py`, `_image.py`) never changes it. The same image also holds the HyperFrames runtime and GSAP (`/opt/renderer/vendor`, read-only), fetched at build from pinned npm tarballs and never committed (PF-a1, D19; `providers/renderer/hf-runtime/`), which makes its tag change once. With PF-a2 the ffmpeg engine draws a second kind of page with them: an admitted HyperFrames component, served by `_hf_host.py` from the image's registry folder with only two edits (E1: the CDN GSAP script becomes the vendored one; E2: a font family name becomes the host's), under `connect-src 'none'` and the request interception, with no freeze, no determinism lint and no frame reuse. Because such a page can draw anywhere, two exact pixel gates (`_alpha_gate.py`) refuse any alpha in the face box or at or below the top of the caption band on every frame it wrote, and a block with no recorded determinism test at its served hash and the loaded runtime's hash is `block_not_proven`. The allowlist is empty. PF-a3 added the admission tool (`ffmpeg.py admit-block`, with `_inner.py admit-check` in the container: for each sample three forward runs and one reverse run, each in a fresh browser, identical frame hashes, no blocked request, the exact gates and the font check) and admitted spring-pop as a staged entry (`hf-runtime/staged/spring-pop.json`): validated, recorded, never loaded by the catalogue, because the port `hf:spring-pop` holds the name and is kept (decision `2026-11-24-pf-a3-admission.md`). The HyperFrames engine's own image (`openhora-hyperframes`) is retired: `scripts/doctor.py --remove-old-images` still removes the old tags from a machine (`RETIRED_IMAGE_REPOSITORIES`, only with `--confirmed`). `scripts/doctor.py` names each family's definition module and finds the images of earlier definitions to remove.

## Dependencies

- `providers/_container.py`: the one container lifecycle (the docker client, the local-daemon check, the run command, the stderr cap, the reaping) behind both providers' function names. This page's providers never call docker another way.
- `providers/resolve.py`: `ROLES` (`transcriber`, `renderer`) and `CLASS_DEFAULTS` (`renderer:video` is `ffmpeg`).
- `shared/references/video-presets.json`: the vocabulary of presets and their typed parameters, read by flag (`--vocabulary`).
- `skills/mkt-social-copy/scripts/check_script.py`: the post-writing skill's own checker, which `align` and `storyboard` run isolated inside the container and whose refusal is final.
- The shared redaction copy: `providers/renderer/_redact.py`, a generated copy of `shared/scripts/redact.py` (the credential formats `check` scans with), kept identical by `scripts/sync_copies.py`.
- `shared/references/platforms/<platform>.json`: the platform file a render is checked against (`--platform-file`).

## Entry points

Each verb prints one JSON object on stdout and diagnostics on stderr; a refusal is `refused: <closed code> <field>` on the first line, and the text of an input is never echoed. The full flags are in `python3 providers/transcriber/whispercpp.py --help` and `python3 providers/renderer/ffmpeg.py --help`.

| Provider | Verbs |
|---|---|
| `providers/transcriber/whispercpp.py` | `--check [--model <name>]`, `models`, `build (--confirmed \| --dry-run)`, `reap`, `transcribe --in <file> --model <name> --language <code\|auto> --out <transcript.json> [--timestamps word\|ml1\|dtw] [--timeout <s>] [--threads <n>] [--max-seconds <s>] [--memory-mb <n>] [--dry-run]` |
| `providers/renderer/ffmpeg.py` | `--check`, `build (--dry-run \| --confirmed)`, `pin-browser (--dry-run \| --confirmed)`, `reap`, `pin-blocks --confirmed`, `block-params`, and the common verbs `analyse`, `base`, `align`, `check`, `cover`, `still`, `verify`, and the drawing verbs `render` and `storyboard` |

`verify --in <mp4> --platform-file <f> [--sha256 <hex>] [--edl <f>]` checks a stored render in a fresh container: the sha256 (given, or the file's own), ffprobe's facts against the platform's spec, the bt709 tags and, with an edit list, the length. Every renderer verb also takes `--memory-mb`, `--cpus`, `--scratch-mb` and `--timeout`. Exit codes: 0 ok, 1 refused or failed, 2 usage error, 3 not configured.

## The new-video flow and the delivery

The flow `new-video` (`flows/new-video.json`) starts one step task of the kind `media` (`runtime/step_media.py`, `KIND`) with the recording's id and the post.

1. `take`: reads the post (`_take`), takes the platform from its `- Network:` line, needs a video entry in the platform's data file and a script, and binds the recording to the task (`MediaStore.bind`, `runtime/ops_step_seams.py`).
2. `transcribe`, 3. `analyse`, 4. `still` (a side step, `_still_due`), 5. `retakes` (`base --retakes propose`: the rule's proposals, each with a default, `cut` or `keep`, and a closed reason; the review shows a `cut` one as cut by the rule and "Keep it" brings it back, V3e), 6. `align-proposal`: each calls one verb of the transcriber or the renderer through `MediaEngine.call`, whose list of verbs is closed (`MediaEngine.CLASSES`).
7. `review`: the stop "Check the captions" (`_review_decision`).
8. `remap`, 9. `base`, 10. `align`, 11. `check`: the edited transcript, the edit list with the project's theme (`theme.theme_from_text`), the beats with the person's anchors and added animations, and the renderer's check.

- **What is scanned, and when.** `video-media-fetch-picks` calls the renderer's `scan` verb (the common image, a container of its own with no network, on the normalised `asset-<sha12>` files only) once, after the normalisation and the adoption of the files, for every asset of the set, whatever its source tier. It is not in the set document or its hash, so no approval made before P9-a goes stale; `approved.json` gains one additive key, `scan`, the digest of what was shown, which the media step never reads. `scan.json` is not a name the media store lets a step read and is never served (`video-media-sheet-file`).

One-file boxes of open-web files (`video-media-approve-asset`) carry that file's rows.

## The licensed pictures of a video (V9b-3a)

Package V9b-3a (decisions D5 to D14 of the V9b spec): a cutaway or a screenshot slot can take a picture from a library whose licence allows reuse in a published video. The picture is found by
words, picked by the person, fetched, normalised in the renderer's container, approved as a set and only then drawn. **Nothing reaches a render that the person did not see and approve.**

- **Switch.** `media.stock` is a list of 1 to 8 sources of the class `stock:media` (`providers/stock/<name>.py` and its data file), `[]` for none, absent for every source whose data file says it needs

- **The render.** Continue stops (`media_not_approved`) while a pick is not approved; the person approves the set or clears the picks and runs the video again. The engine gets `--asset` and `--asset-sha256`

## The pictures found on the web (V9b-3b)

Package V9b-3b (decisions D6 to D8 of the V9b spec and its amendment of 2026-11-22): a picture can also be searched on the open web by the model that runs the skill `mkt-video-media-search`.
Nobody can check who owns such a file, so it has an approval of its own, after a copyright warning, on top of the approval of the set. **A file found on the web never reaches a render without it.**

- **Switch.** The open-web source is a source of `media.stock` whose data file says `unverified` (by default it is listed first). It is a widening item of its own (`stock=<source>@none`): `accept-config`

- **`video-media-websearch --task T [--confirm]`** (terminal and page; class G, a job). Code decides, in order, with nothing run: the video waits at the caption review; the web source is on and accepted; the
  slots (at most six; a slot that wants a clip is not sent while the engine draws none, and is said); the skill declares `search:web` and no side effect; the routed pair was measured with the web; the day's
  count is under the bound. Without `--confirm` it prints the words and says that this computer will then download a preview of each picture found (up to 16 MiB each) from the sites found (those sites see this computer's address). With it,
  one run of the skill on the open network, with no file of the project and no standing instruction: its prompt is rendered from the slot ids, the kinds and the search words alone, in the form the skill was
  measured on. Its candidates file is read without following a link (at most 64 KiB), copied, and checked by the skill's own script and again by the same rules in code; either failing refuses the file whole.
  The open-web provider fetches one preview of each candidate into the quarantine, and the candidates join the licensed ones in one set (V9b-3c). A candidate with a thumbnail is previewed from it
  (verb `preview`, at most 4 MiB, 40 s); an image with no thumbnail is previewed as the file itself (verb `fetch`, at most 16 MiB, 70 s); a clip with no thumbnail has no preview and no call. Every kept preview's
  width and height are read from its own header bytes (PNG or JPEG), and a candidate whose side is over 8192 px, whose area is over 40,000,000 px, or whose header is not understood is dropped alone
  (counted in `dropped.preview`), since the renderer would refuse the whole sheet for one such picture and would refuse to use it. Licensed previews are not checked this way. The run folder is removed in every case.
- **One set, two searches.** `video-media-find` replaces the licensed candidates and keeps the open-web ones of the same words; `video-media-websearch` replaces the open-web ones and keeps the licensed ones
  of the same words; either one voids the approval. A web candidate shows where it was found, what its page claims (a claim, never checked), a note when it is a still of a screen work, and the page address as
  plain text on this computer's own page and the terminal.
- **`video-media-approve-asset --task T --slot S --sha256 H [--confirm-digits <12 hex>]`** (terminal and page; never the interpreter, messaging, the MCP mode or the local network's socket; no bulk form). After the set is
  approved, one file at a time: without `--confirm-digits` it prints the copyright warning, the host, the page and the claim; with the first 12 digits of the file's sha256 it writes
  `approved.json["unverified"][S] = {sha256, task, at, channel}`. The step renders the file only with that record for this task and this sha256 (limit L80). The set approval no longer waits for these:
  it lists the slots that still need one (`needs_own_approval`) and the ones that have it (`own_approved`), and approving the same set again keeps them.
- **Credits and pages.** The download answer lists `source_pages` ("Source page: <page>"); a card never shows a page address.

## Known limits and improvements

- The storyboard is asked for, never automatic (V5-1): no flow draws it by itself, and it is drawn by the ffmpeg engine for every project (see "The storyboard of a post"). The page's storyboard needs a PNG to show, so the demo copy of the interface says it has no engine; the live leg is one docker-gated test of `runtime/tests/test_media_storyboard.py` (`WB_RENDERER_DOCKER_TESTS=1`), written and not run by V5-1.
- The ffmpeg image installs the DejaVu system font (`fonts-dejavu-core`) and has no last layer that fails on a font outside the allow-list, which condition 6 of the V0 decision asks for (the HyperFrames image had that layer, OPEN-3, until PF-b). A purge layer for this image is left to a later package.
- `selfcheck` is the one inner verb that is not a drawing verb and still imports the drawing part (`_cdp`), because it reports the container mode.
- **The aside, the one effect preset.** `aside` (kind `effect` in `shared/references/video-presets.json`) turns the speaker's shot black and white and adds an echo to the voice for one beat, with a hard cut on both edges; at most one a video, any role, never with a punch or a layout on its beat (the script checker's `effect_repeated`, `effect_with_punch`, `effect_with_layout`, held again by the renderer's `check_beats`). Both engines draw the grey (the mono grade rows) and the echo (the ffmpeg engine in its compose graph, the HyperFrames engine at its encode stage). Not verified: a render in the rebuilt image. See `providers/renderer/README.md`.
- **The frame band (V9b-2).** The engine draws `oh:cutaway` (and `oh:screenshot`, a second block of the `cutaway` preset) as a whole-frame layer under the cards and the captions; the pictures come as `--asset` PNG files (what `asset-sheet` normalised). The HyperFrames engine's own gates for it went with that engine (PF-b). See `providers/renderer/README.md`.
- **Clips on the ffmpeg engine (V9b-5a).** `asset-sheet` takes clips beside pictures (an MP4, MOV or WebM told by its first bytes; the first video stream only; h264, hevc, vp8, vp9, and av1 only when the image's ffmpeg has a software decoder; at most 7680x4320; the first 10 seconds) and, in `full` mode, writes one pinned form: H.264 High, yuv420p, bt709 tagged, a constant `--fps` (24 to 60, 30 by default), no audio, the long side 1920, `asset-<sha12>.mp4`. The ffmpeg engine's compose draws such a clip under an `oh:cutaway` entry, under the beat layer and over the speaker, on the entry's frames only (the clip fills the frame, or sits whole over a blurred, tinted copy of itself, from the same look values the page uses), and the page draws only the label chip. Only the hard cut is drawn for a clip (`clip_transition` otherwise), and only `oh:cutaway` draws one (`asset_type` for another block). `asset_kinds` was `["image"]` on both engines until V9b-5c flipped it to `["image", "clip"]` (see the entry "Clips reach the runtime"); the HyperFrames engine draws one since V9b-5b (next entry). Not verified: the image rebuild, a clip that is not synthetic, the bytes at 4 and 8 cores in the image, the maintainer's C10. See `providers/renderer/README.md` ("Clips") and `docs/decisions/2026-11-21-v9b-5a-clips-ffmpeg.md`.
- **Clips reach the runtime (V9b-5c).** The engine file says `asset_kinds` is `["image", "clip"]` (`pin-blocks --confirmed` rewrote the pins and the catalogue; no image tag changes, since the image holds no `blocks/` catalogue), so a person can pick a clip for a slot. Only an `oh:cutaway` draws a clip, so a clip pick on a slot another block draws is refused at `fetch-picks` before any fetch (`clip_block`). `fetch-picks` reads the edit list's frame rate, passes it to `asset-sheet` and writes it as `clip_fps` beside the set (outside the hashed document), so the engine draws a clip at the edit list's rate; the align step refuses a set whose rate is not the final edit list's (`clip_fps_changed`). A clip is fetched with a cap of 64 MiB (the renderer's own staging cap), kept at its first 10 seconds, and refused when shorter than 1.5 s plus three frames (`clip_too_short`). The align step ends a clip cutaway with its clip: `step_media.fit_clip_entries` lowers `word_to` to the last word whose beat fits the clip with two frames to spare, with the arithmetic of the renderer's timeline (a test compares the numbers and a seeded sweep runs the renderer's own timeline and the ffmpeg clip rows on what the runtime wrote); a beat whose first word alone is longer than its clip fails the step (`clip_too_short`). The page shows only the set's sheet for a clip (its tile is the clip's frame at 0.5 s with the clip marker); the open web is a source of clips (the same warning and own approval as for its pictures). The phone card still says "Picture" for a clip. Not verified: a real clip, how often a web search returns a direct clip link with a thumbnail, the bytes in the images, the maintainer's C10. See `docs/decisions/2026-11-23-v9b-5c-clip-choice.md`. A web clip with no thumbnail is kept as a candidate with no preview tile (K4, B1: no provider call at search time, an empty cell on the preview sheet, a page line that says so); it can be picked, and its frame is on `sheet.png` after the fetch and before the approval.
- **PF-a4 (the ports on the ffmpeg engine).** The five tier-B ports draw on both engines: the ffmpeg engine builds one `/h/` page per caption chunk and per beat (`_hf_port.py`) under the second page contract, with the fragment lint and the band clip kept, and only when the port's `block.json` carries a recorded determinism test (`ffmpeg.py admit-block --port`). The face rule was removed for every overlay on 2026-11-24: the face box places the bands, nothing is refused for touching it; the line at 1560 and the band clip stay (`docs/decisions/` file of PF-a4). Since M2 (PF-a4f, 2026-11-26) the ffmpeg engine's presets for `caption`, `keyword`, `number` and `quote` name the ports `hf:caption-highlight`, `hf:spring-pop`, `hf:count-up` and `hf:testimonial-card`, as the old engine's do; the other presets keep their `oh:` pages (`docs/decisions/2026-11-26-pf-a4f-m2-defaults.md`).
- The `hf:` allowlist is empty (V3b-3 admitted no registry component) and the committed `blocks/engines/ffmpeg.json` runs `renderat`, `hf` and `gsap`, with the five tier-B ports of V3b-4 (`blocks/hf/<name>/`) as its defaults for `caption`, `keyword`, `number` and `quote` (since M2, PF-a4f) and `oh:list` for `list`; a block whose parameters differ from its preset's cannot be named by a beat yet (OPEN-6 of the V3b0 spec).
- The synthetic renders in CI prove the container path of the engine on a generated recording (the `renderer` job, a matrix of three legs that run at once (CI-1b); the `hyperframes` job went with the engine, PF-b); a render of a real recording on the maintainer's machine is a separate, manual step.
- The review-only presets `mark`, `sticker` and `nametag` (V9a-1) and `focus_card` (P4b) and `title_card` (P4c) can be added at review but a script cannot ask for them; moving one into the script is a change of `mkt-social-copy` and of the shared vocabulary. The look of the three marks, and why the keyword card once drew at the top left (the inline layout of V9a-1 is a remedy, not a proven cause), wait for the C10 sheets and the live leg of V9a-1.
- Picking the block of a script beat's preset (G14) and a preview of an added animation are later (V1b3 OPEN-5, OPEN-10).
- A missing setup is found at the render, after the caption review, not at the start: the render is refused `not_configured` (the review is kept); there is no other engine to replace it (since PF-b1 the class default is ffmpeg and the name hyperframes is read as ffmpeg: a project that never named an engine is drawn by ffmpeg, in Inter for a theme that names no font, B2). Every default video uses the HyperFrames caption block, drawn by the ffmpeg engine under the second contract; the real-size render took 963 s on the old engine and 364 s on ffmpeg with the oh: pages at 4 cpus (`providers/renderer/reports/engine-contract-2026-11-10-arm64.json`, retired engine), and the ports (M2) cost more than the oh: pages (the F1 short went from 44.0 s to 86.5 s, `2026-11-26-pf-a4f-m2-defaults.md`).

On a messaging app the delivery is approved from a card (decision 14): the render is its own preview when it is at most 15 MiB, and a larger render gets a copy that fits from the renderer's `preview` verb (V3d), the bridge sends it as a video before the deliver card, and the card offers its approval only after the provider confirmed it. When that copy cannot be made, the delivery is approved in the terminal or on the page. The body of the card is said in the project's language (`CARD_VIDEO_*` lines), and the title is the fixed `Deliver the video`.
- Effects (V9a-3): the face check no longer proves the face is unchanged on the frames of a grade (flash, dip, mono, tint), only that both engines drew the same picture there and that no overlay covers it (the maintainer's answer to OPEN-8, 2026-11-10); mono goes through two bt709 conversions around the CSS matrix on the ffmpeg engine (every frame of a range that has a mono row, one or two grey levels off a pure conversion), so the live leg L3 measures whether 30 dB holds, and the first remedy if not is the drawing method, never the threshold. A drop of the script's punch at review (`p<beat>`) is checked against the range 1 to 12 only, because the edit operation does not pass the set of the script's punch beats yet (`ops_media_edit.py` is outside the package); the align step ignores a drop that names no punch. The interface has no control for effects yet (`captions-edit` only).

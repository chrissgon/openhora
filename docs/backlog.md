# Backlog: workbench tasks

Work on the workbench itself that is not writing a skill: tooling, checks, rules, repository settings. Skills, flows and agents are tracked in [inventory.md](inventory.md); an item here that becomes a skill also gets a row there.

- **Only open items are here.** A closed item is deleted, with the commit that closes it; its text stays in git history. Items closed before 2026-10-14 were in `docs/backlog-archive.md` (removed on 2026-10-14; `git show d3e60770:docs/backlog-archive.md`); the items removed on 2026-10-15 are in `git show bc830832:docs/backlog.md`; the items closed on 2026-10-16 (T15, T30 and R10 by the maintainer's decisions of 2026-10-15, and S16, S18 and PL-validation by their own pull requests, #421, #420 and #423) are in `git show 156a08cb:docs/backlog.md`. Ids are never reused and never renumbered: they are cited in contracts, providers, skills, `decisions.md` and commits.
- **Where each item is handled** is said in the item: its `Plan:` line names who does it and when, its `Trigger:` line, where it has one, names the event that starts it, and its `Decision:` line, where it has one, names what the maintainer decides before it is done. The packages of the work in progress are in the delegation plan, `docs/architecture/delegation-platform-plan-2026-10-14.md`; the earlier plan of phases A to H, `docs/architecture/final-plan-2026-10-02.md` (removed on 2026-10-14; `git show d3e60770:docs/architecture/final-plan-2026-10-02.md`), is history.
- Each item says where it came from, so none is written from generic knowledge. Delete an item when its "Done when" holds, in the pull request that makes it true.
- **Words about a skill's status.** How skills are tested and ranked is the reliability model ([architecture/reliability-model-2026-10-02.md](architecture/reliability-model-2026-10-02.md)): a new skill is done when its first full test has passed, and a skill is then ranked on each model by a band (`reliable`, `watch`, `needs a test`) computed from its lab evidence. Nothing prints the words `draft`, `evaluated` and `stale` of the first round any more.

## Security

The workbench is a set of instructions that models execute with a terminal, files and network access. The threats are the ones that turn those instructions against the user: secrets in the repository, text hidden from the human reviewer, scripts that run more than they say, and skills that act on the outside world without declaring it.

## 2026-11-24: The second page contract in the ffmpeg engine (PF-a2; plan video quality v6)

**Context.** A HyperFrames registry component cannot live under our first page contract (our CSP, `FREEZE_JS`, `__setup`/`__frame`, the DOM-signature reuse of frames): it needs GSAP, the HyperFrames runtime and its virtual-time shims, and it draws wherever it likes. PF-a2 adds a second contract beside the first, for admitted pages only. The allowlist stays empty (PF-a3 admits the first component); the contract is tested with a fictional component.

**Decision.**
- **The maintainer's words, 2026-11-24, verbatim:** authorising the work, "Sim, comece (Recomendado)"; **M1, the trade of guards (R3-2): "Aceito (Recomendado)"**; M2, option (a) (spring-pop admitted staged, the other four ports moved onto the second contract in PF-a4): "Pode (Recomendado)".
- **M1 as accepted.** The second contract drops four guards: the determinism lint (replaced by a recorded determinism test, PF-a3), the proxy sandbox of `window`, the band clip of the card band, and the font read over CDP per frame (replaced by the same check run in page). It keeps six: the container; `connect-src 'none'` and the request interception (a recorded block fails the render); the exact alpha face gate and caption-line gate on every frame an admitted page draws; the hash pin of every served file, checked at render; the recorded determinism test at those hashes and at the runtime's; and a reduced escape lint with planted cases.
- **Runtimes.** The ffmpeg engine's `runtimes` are `["renderat", "hf"]`. An entry of `blocks/hf/allowlist.json` with `implementations: {"hf": ...}` is drawn by the second contract and only if it carries a determinism record (4 runs, 0 blocked) at its served hash and at the loaded runtime's hash (`block_not_proven` otherwise). The runtime hash covers GSAP, the runtime, the five shims as served (fps filled in), the host's version and the browser's version string: raising any of them expires every record.
- **Pages.** `_cdp.py` serves `/h/` pages under `CSP_ADMITTED` and every other page under `CSP`; `FREEZE_JS` is byte-identical (its sha256 is pinned in a test). `_hf_host.py` builds one page per beat (early shims, vendored GSAP, runtime, the component's template with the id the runtime looks for, a host root at the card zone's box with our values and theme, render mode, bridge). Edits are E1 (the CDN GSAP line) and E2 (a font family name) and nothing else; any other difference is `block_hash`. `_hf_lint.py` is the reduced escape lint (it says in its docstring that a text lint is evadable by computed keys, and a planted variant shows it). `_alpha_gate.py` reads, with one ffmpeg pass per range, the highest alpha in the rounded face box, below the caption band's top and in the whole frame, with no threshold.
- **Deviations from the written spec, each forced by a fact.** (1) The readiness expression looks for `#oh-host > *`, not `#oh-host [data-composition-id]`: the real runtime renames that attribute (`data-hf-authored-id`) while it mounts. (2) `files` names are relative to `component` (the registry folder); an entry also carries `font_map` (the host family each E2 edit renames to), which the spec's "per the entry's map" implies; `natural_duration` is the block's existing field. (3) `theme_vars` roles are a theme colour token or `font:<role>`. (4) A missing determinism record is `block_schema` (the entry is refused when the catalogue loads), a mismatched one is `block_not_proven`; the existing code name `block_schema` is kept. (5) The gate runs once per range of each admitted beat, with that beat's own face box and the top of its own caption band. (6) The lint also runs at render. (7) Test mode only: `RENDERER_HF_RUNTIME_DIR`, `--vendor`, `--hf-registry`, and `RENDERER_HF_REGISTRY_DIR` (a read-only mount over the image's registry folder for the live legs). (8) The storyboard draws these blocks with no pixel gate and names them in `advisory`.

**What it saves and what it loses (principle 13).** It saves the HyperFrames engine's second image and second browser for pages that need GSAP or the runtime, and lets the ffmpeg engine draw them. It loses the four guards of M1: a page can run real code in its own throwaway page, can attempt requests (blocked and recorded, and a recorded block fails the render), and can put pixels outside the face box and above the caption band during its entry only as far as the gates allow, which is nowhere on a frame it wrote. A text lint is not the wall; the page policy, the interception and the pixel gates are.

**Verified.** Offline, with the host's Chromium and ffmpeg and a stand-in for the runtime: the clean control twice byte-identical; every planted variant refused with its code and first frame (alpha 1/255 in the face box on frames 5 to 7 is found on frame 5; a draw below the line; nothing drawn; a computed-key `fetch` passes the lint and is `blocked_request`; a family not declared is `font_not_allowed`; `FontFace` and `localStorage` are `block_lint`; an opaque frame is `overlay_hits_face`, and with the corner cut removed `frame_not_rgba`; a mismatched record is `block_not_proven`; a changed file is `block_hash`). The same variants were also run on the host against the image's real runtime and GSAP, with the same results. Unit tests for the lint (every rule, its near miss), the gate on synthetic frames (exact edges), the host page (a golden, a planted `'"><script>` value), the CDP driver with a fake pipe and the frame loop with fake pages.

**Live step 3 (the supervisor's, run here with the built image).** with the image `openhora-renderer:e1d1ed03f4e7` (the common image, the real runtime and GSAP, the fictional component mounted from a test registry folder): leg F10 of `test_engine_contract_live.py` passes (82 s). The clean control twice is one sha256, and its summary names the served and the runtime hash. Every planted variant is refused with its code and leaves nothing: `face_dot` `overlay_hits_face` frame start+5, `below_line` `caption_below_line` frame start+4, `nothing` `block_not_drawn`, `opaque` `overlay_hits_face` frame start+3, `opaque_no_clip` `frame_not_rgba`, `computed_fetch` `blocked_request`, `system_font` `font_not_allowed`, `fontface` and `lint_storage` `block_lint`, a mismatched record `block_not_proven`. The renderAt path: the same short case (keyword, number, cutaway, pip) rendered through the host in the new image twice and in an image built from the base commit `a80b8884` gives the same sha256 all three times (`33968feb974bd68bc0e57549712c95664273923c37bb5e15a7c67af1c346a3a7`). A first live run found that the spec's readiness expression never became true with the real runtime (it renames the component's `data-composition-id`); it is fixed above. The real runtime mounted the template with no request and no exception; GSAP loaded twice (the host's tag and the E1 script) with no error

**Not verified here.** That GSAP loaded by the host and again by the component's E1 script is harmless beyond the fictional component (no error, no blocked request was seen); the determinism comparator and the `Math.random` variant (PF-a3's admission tool); that a real registry component, not the fictional one, mounts the same way (PF-a3).

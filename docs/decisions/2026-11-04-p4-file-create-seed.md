## 2026-11-04: a file the interpreter read is created from its spans (P4 of SPEC-ACEITE-FIX-READING, limits L61 and L63, no model call, no lab run)

Row 29 of the acceptance run ("cria um arquivo lista-teste.txt no drive com: arroz, feijao, cafe") ended in `IX_CANNOT_WRITE`: the model had read a `file-create` with a name, a content and a folder, but the closed forms of the files family need "chamado <name>", so nothing opened. Package P4 builds the seed, as BL7-5 did for message numbers.

- **The order.** `ops_interpret._carry_out` still tries the closed forms first. When they read nothing and the decision has a `content` span, `ops_natural_files.seed` builds the seed and `ops_natural_writes.open_line(seed=...)` opens the family (`_read` returns the seed's slots, never a re-reading of the line). A line the closed forms read is opened as before.
- **The parts.** `name`, `content` and `folder` are spans of the line the interpreter's check verified, with the origin `line-span`. A `folder` span that is only a word for a service is no folder: the bare "drive" (`ops_file_read.GENERIC`) names nothing, so the family asks which account when two list folders; "onedrive" names the account (`ops_file_read._service_of`) and the family does not ask. A folder the account does not list is asked as before (`NW_ASK_FOLDER`).
- **What is missing.** A decision with no `name` is asked the name (`NW_ASK_FILE_NAME`, as for a name with no extension). A decision with no `content` gives no seed: the closed forms read nothing either, so the person is told it could not be prepared (`IX_CANNOT_WRITE`). The spec asked the family to ask the content; no phrase key asks it today, and adding one is a phrase-table change the package did not list, so it is left to the maintainer (a new key `NW_ASK_FILE_CONTENT` and one `ask_spec("content", ...)` in `ops_natural_files._create`).
- **The card is unchanged.** The create card, its hash and its approval are the ones of the closed forms; the gate's provenance check passes on the seed's origins.
- **Golden.** `sample.ix_test.0763` and `sample.ix_test.0420` moved from `IX_CANNOT_WRITE` to the account question of a two-account world (named in the spec's allowed list); `sample.ix_test.0119` (a file-replace) did not move. The rows were replaced with `entry_corpus_build.py --re-record`, the spec being the reviewed decision.
- **Tests.** `runtime/tests/test_file_create_seed.py`.

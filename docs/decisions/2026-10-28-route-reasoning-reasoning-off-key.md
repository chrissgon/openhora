## 2026-10-28: a route says how "no reasoning" is asked: the optional row key `reasoning_off` (`disable` by default, `minimal` for the first fallback row) (ROUTE-REASONING, S41-10; limit L63(2); no model call, no provider call, no lab run, fingerprint unchanged)

- **The fact (measured by the maintainer on 2026-10-27 through the router, outside the repository).** The first fallback route `or-gemini-3.5-flash-lite` (pin `google-vertex`, `zdr` true) answers HTTP 400 "Reasoning is mandatory for this endpoint and cannot be disabled" to any body that carries `"reasoning": {"enabled": false}`, which `providers/model/chat-http.py` sent for every call with `params.reasoning` `off`, that is every daily interpreter call; so the route could not be called (`E_HTTP`). With `"reasoning": {"effort": "minimal"}`, or with no reasoning field, it answers 200 with 0 reasoning tokens in 1.3 to 2.0 seconds at about US$ 0.000825 a call. The DeepSeek row works with `{enabled: false}`.
- **Source read on 2026-10-27.** The router's reasoning-tokens guide (https://openrouter.ai/docs/use-cases/reasoning-tokens): `effort` takes `max`, `xhigh`, `high`, `medium`, `low`, `minimal` or `none`, `minimal` being about 10 percent of `max_tokens`; `enabled: true` turns reasoning on at the medium level; a model whose entry in the models list is `mandatory` rejects `effort: none`, and clients should not send it. The page does not say what `enabled: false` does for such a model; the measured 400 is the evidence. `{effort: minimal}` is therefore the lowest setting the page names that a mandatory-reasoning model accepts (measured), and the field stays a per-row choice, not a global one.
- **The change.** A route row may carry `reasoning_off`, closed to `disable` (today's body, `{"enabled": false}`, the default when the key is absent) and `minimal` (`{"effort": "minimal"}`). `interpreter_route.load` refuses the whole routes file for any other value, as it does for the other keys; `stdin_route` shows the key to the provider, and so hashes it, only when the row has it (as `pin_reply`), and `evals/interpreter_status.py` hashes it the same way. `chat-http.py` accepts the key (any other value is `E_USAGE`) and `build_body` sends the form it names when `params.reasoning` is `off`; `on` sends no field. Only the `or-gemini-3.5-flash-lite` row carries `minimal`.

## 2026-10-30: the start and the body of a run, and the gate, move to ops_task_run (44-C4a; SPEC-44C4, OPEN-C1 B, OPEN-C2, OPEN-C4-1 to OPEN-C4-5)

**Decision.** The start and the body of a task run leave `runtime/ops.py` for the new `runtime/ops_task_run.py`, with the gate where a run's effect becomes a pending approval. 18 names: `MANDATORY_LINE`, `PREPARE_ERRORS`, `_prepare_run`, `_run_start`, `_run_body`, `_ending`, `_effect_kind`, `_effect_or_review`, `_tmp_files`, `_gate_payload`, `_git`, `_request_run_dirs`, `_code_state`, `_reader`, `EMPTY_CHANGESET`, `_changeset_of`, `_project_bytes` and `_dependencies` (414 code lines). The bodies are byte for byte what they were; the one line that differs from the base is `_prepare_run`'s route (`ops_models.route(` where `ops.py` called its `_route`, the same call, as `_router_call` has done since 44-C3). `ops.py` re-exports every moved name after the marker, so `dir(ops)` is the base's plus the module name `ops_task_run`.

**Principle 11.** The path where a run's effect becomes a pending approval (`_run_body`, `_gate_payload`, `_effect_or_review`, `effects.write`, then the store) moves whole and unchanged. Everything that reads the payload and its hash stays where it was: `approve`, `_approve_effect`, `_execute_effect`, the cards and the grants. A probe that records every pending decision, every effect document and every recovered payload (the gate capture of the spec, on 111 test files) gave the same records before and after the move. That probe found a gap in the tests: a wrong `payload_file_sha256` in the effect document passed all 2,423 tests of the 65 files that mention the hash. `runtime/tests/test_gate_hash_chain.py` closes it (OPEN-C4-4): it recomputes, from the files' own bytes, that the decision's hash is the hash of the effect document, that the document carries the hash of the payload the skill showed (limit L16), and that an approval with another hash executes nothing; two planted wrong hashes (in the document, in the decision) make its oracle fail.

**What the callers do now.** `ops_runs.run_task` and `ops_runs._start` reach the body and the start through `_task_run_module()`, `importlib.import_module("ops_task_run")` at call time: `ops_task_run` imports `ops_runs` for the pieces of a run, so `ops_runs` cannot import it back. It is a `cycle:` row (`ops_runs -> ops_task_run`) in `test_import_breakers.py`. The edge `ops_runs -> ops` stays, for the round that 44-C4b moves. `ops.py`'s `deps` reads `_project_bytes` as `ops_task_run._project_bytes`, the one caller left there.

**Choices the supervisor made.** `handler_call` (an operation of the table) stays in `ops.py`, so C4 moves 38 of the 41 names of the first closure (OPEN-C4-1); `ops_task_run` holds its own copy of `_read`, five lines identical to those of `ops.py` and `ops_config.py` (OPEN-C4-2); `ops_runs` keeps the functions of the round (OPEN-C4-3); the helper is `_task_run_module` and the local `task_run` (OPEN-C4-5).

**Tests re-pointed.** `test_changeset_missing.py` patched `ops._git` and `ops._request_run_dirs`, which the moved `_code_state` no longer reads from `ops`; the patches are on `ops_task_run` now. The golden kit of `entry_kit.py` stubs `ops_runs._use_start`; it now also counts the starts of the real recorder that reach `ops_runs._record` and asserts at the close of every world that there were none, so a stub on a wrong target fails the replay (the 44-C3 review measured 303 real starts with the stub removed).

**Budgets.** `LAZY_CALLS_BUDGET` 58 to 59 and `LAZY_EDGES_BUDGET` 47 to 48 (the file's own AST count; one edge in, none out), `PLAIN_DEBT_BUDGET` 0. `OPS_PY_BUDGET` 2,186 to 1,772 (414 code lines moved; headroom 32 as before). `ops_task_run.py` is 498 lines and `ops_runs.py` 1,021, both under the 1,200 of a sibling.

**Alternatives rejected.** Moving `handler_call` with the round (it is an operation: operations do not move under OPEN-C1 B). Reading `_read` through `core` (a 17th shared name and six callers in `ops.py` changed, to save five lines). Moving the functions of `ops_runs` that start the round (it re-points more patches than this package owns).

**Not changed.** No rule, phrase, policy, approval, limit or card hash; no new behaviour. The entry golden is untouched and replays identically.

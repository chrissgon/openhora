## 2026-11-24: The admission of HyperFrames registry blocks (PF-a3; plan video quality v6)

**Context.** PF-a2 added the second page contract and left the allowlist empty. PF-a3 adds the tool that admits a registry component to it, and admits the first one, spring-pop, with a recorded determinism test on the real runtime.

**Decision.**
- **The tool.** `ffmpeg.py admit-block --source <clone at the pinned commit> --component <path> --entry <our fields> --vocabulary <f> [--stage] [--confirmed]`. Without `--confirmed` it lints, hashes and prints the plan and starts no container. With it, the container runs `_inner.py admit-check` (`_admit_check.py`): for each sample, three forward runs and one reverse run at 1080x1920, each in a fresh browser; the sha256 of every frame of the four lists must be identical (the pure comparator, `compare_runs`); no blocked request, exception or policy violation; the exact face and caption-line gates and the font check pass at the default face box. Only then does the tool write the `registry.sha256` row, a NOTICE entry and the entry with its record, or `hf-runtime/staged/<id>.json` with `--stage` or when another block holds the name (`name_taken`). A clone at another commit is `admitted_commit`; any other edit than E1 and E2 is `block_edit`.
- **Spring-pop's entry** (`hf-runtime/entries/spring-pop.json`): `text` (max 24) and `color`, `overshoot` 1.4 and `fromScale` 0.9 fixed, six theme variables mapped (never `--bg`), edits E1 and E2:Inter, three samples (shortest, 24 characters, pt-BR with accents). It needed no edit beyond E1 and E2. To let `color` and a theme mapping of `--brand` coexist, `_hf_host.values_for` now resolves a palette token to the theme colour and lets a bound parameter win over the theme default for the same property.
- **The measured record** (supervisor's run, image `openhora-renderer:4d3d46922f7a`): served_sha256 `e10158be254745a17099aab005d402e579a2843f8ba962937a24c59ed6648a7f`, runtime_sha256 `491a22ffea0bf65cedc4389ddda9c31e2906c7adac05726333e4d4f422bf42ea`, 3 samples, 162 frames, 4 runs, 0 blocked, 36.64 s, 2026-11-24. Staged because `hf:spring-pop` is the tier-B port's name.
- **Raster-history finding.** With the stand-in runtime and the host's Chrome, a plain opacity fade left the frames after it rasterised differently from the same frames sought first: forward runs agreed, the reverse run did not (a real property of the page's layers, found only because one run seeks the last frame first). It did not show on the real spring-pop. A test pins it (`will-change: opacity` removes it).
- **M2, the maintainer's words:** "Pode (Recomendado)", option (a): spring-pop admitted staged; the other four ports move to the second contract in PF-a4. <!-- validate: allow english-only -- the maintainer's own words, quoted -->
- **C10, the parity result and the maintainer's words.** Original on the ffmpeg engine against the `hf:spring-pop` port on the HyperFrames engine, same three texts: the original took 21.6 to 22.1 s per render, the port 45.2 to 57.2 s. The original draws at its native pixel size, about a third of the port's height, so its text is small on a 1080x1920 frame; the port is large and bold. Making the original bigger needs an edit beyond E1 and E2, which the conditions do not allow. The maintainer chose: "Manter o nosso port (Recomendado)". <!-- validate: allow english-only -- the maintainer's own words, quoted --> Consequence: the original stays staged and is not activated, PF-b does not activate it, and spring-pop's port joins the kept ports for PF-a4 (moved to the ffmpeg engine under the second contract).
- **Generated table.** On the maintainer's "Sim, pode rodar (Recomendado)", <!-- validate: allow english-only -- the maintainer's own words, quoted --> the supervisor ran `architecture_tables.py --write` for the verbs table after `admit-block` was added to `providers/CONTRACT.md`.

**What it saves and what it loses (principle 13).** It saves admitting a component by hand: every admission is a recorded measurement at the served and runtime hashes, refused in code, and the real original is kept as evidence. It loses speed and a look: the original renders in about half the port's time but draws small, and nothing is activated, so no video changes. The test costs about 37 s for three samples; a raise of GSAP, the runtime, a shim, the host or the browser expires the record.

**Verified.** Offline: the comparator, the plan (commit, edits, lint, name, staging, writes), the host verb through the fake docker, and the measurement in the container's entry point on the host with a stand-in runtime (clean control passes; Math.random, face, line, nothing-drawn, computed-fetch, font and FontFace variants refused with their codes). Live: the admission of spring-pop in the image with the real runtime (record above), and the parity sheet.

**Not verified.** That GSAP loaded twice (the host tag and E1) is harmless beyond this component and the stand-in (no error or blocked request appeared in the live admission); other Chrome versions' raster behaviour for the history effect; the parity look of the other four originals (they are not admitted).

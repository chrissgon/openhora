## 2026-10-28: the Gemini fallback row names the provider the router answers with (BATCH-KEEPER gemini-pin-reply; no model call, no lab run, fingerprint unchanged)

The maintainer's probe of the fallback route `or-gemini-3.5-flash-lite` ended with `chat-http: provider google` and `E_PIN`: the router's reply names the pinned Vertex provider `google`, while the row's pin, the slug the request asks for, is `google-vertex`. S41-10 built `pin_reply` for this case: the exact name the router gives the pinned provider in its reply, compared without case, part of the row's hash.

- **Change.** The row `or-gemini-3.5-flash-lite` of `runtime/interpreter_routes.json` has `pin_reply: "google"` (it had `google-vertex`, written before a probe showed the name). The pin stays `order: ["google-vertex"]`, so the request still asks for Vertex and no other provider (`allow_fallbacks` false); only the check of the reply compares with the name the router gives. The reply of the other provider is still `E_PIN`: `google-vertex` as a reply is now refused for this row, since it is neither the name measured nor the reply of the asked route.
- **The hash.** The row's `route_sha256` moves from `30af746728a31cfed29323e8c260b0a2ed4a3cfd278fbb536e7a300394c62da2` to `a48acfd83dbc6825e2e4b56263215a4e3bcc3015a393fffa9f0fd2b53af3c602`, which `scripts/tests/pinned_hashes.json` holds (key `route_or_gemini_3_5_flash_lite`), and the fallback tests read from there. The DeepSeek row and the second fallback row (`azure`) are unchanged. No enabling entry holds the old hash: `runtime/interpreter_enable.json` is untouched and the fallback stays off; an entry for this row, when the maintainer accepts one, pins the new hash.
- **Tests.** `runtime/tests/test_turn_gate_fallback.py` no longer expects `pin_reply` to equal the pin for both fallback rows: it writes out `google` for the Gemini row and `azure` for the second. `runtime/tests/test_route_reasoning.py` keeps its literal hash of the earlier row (no `reasoning_off`) by restoring the earlier `pin_reply` in the row it hashes.

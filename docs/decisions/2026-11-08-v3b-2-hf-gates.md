## 2026-11-08: the DOM-box, 1560 and pixel gates of the HyperFrames engine (V3b-2; no measurement change, no skill changed, no lab run)

**What.** A render of the HyperFrames engine that draws is now gated, and nothing turns the gates off. After `hyperframes render`, the drawing container runs
`hyperframes-image/hf_measure.mjs`: it serves the project on the loopback, seeks every output frame with the renderer's own `renderSeek` and writes
`boxes.json`, the boxes the page itself reports (every visible box inside a `gsap` instance clipped to its band, every `data-zone` box of a `renderat`
page, and the rectangles of the text, unclipped). The `encode` container (`_hf_gate.py`, a common module, so `_layout` and `_edl` are not written twice)
reads it by its sha256 and refuses, before encoding, a box that touches the face box of its frame (`overlay_hits_face`) and a caption box whose bottom is
below the band's bottom, 1560 on the presets (`caption_below_line`), with the ffmpeg engine's own arithmetic and refusal codes. After the encode it
compares the face region of every kept range of the ProRes intermediate with the same region of the undrawn base (the proxy, cut and zoomed by
`_media.base_graph`, the function `compose_argv` now builds its picture from) frame by frame with ffmpeg's `psnr`, and refuses `face_pixels_changed`
under `PIXEL_MIN_PSNR_DB` (30 dB). The candidate is written only when both pass. `hyperframes.py` loses `GATES_BUILT` and the `gates_not_built`
refusal; a composed render whose drawing container left no `boxes.json`, or whose encode stage reported no gate, is refused. The result adds `gate`
(`frames`, `boxes`, `lowest_caption_bottom`, `pixel_min_psnr_db`, `pixel_ranges`) and `stage_seconds.measure` and `.pixel`; every field is additive and a
base-only render has none.

**Why.** Plan row V3b (conditions 1-9, decisions VD3, VD9, VD12, VD13, VD15 of `2026-11-07-v0-short-video-hyperframes.md`); V3b spec sections 6.1 to 6.10 and
OPEN-9 and OPEN-10. Principle 11: the gates are code in the encode container and in the host's checks, not a prompt and not a test. The pixel check buys what
the DOM cannot report (a canvas, a pseudo-element, a shadow or a filter drawn over the face with no box of its own).

**Settled by the supervisor on the spec's recommendation (2026-11-07), not the maintainer's word.** OPEN-9: the threshold is 30 dB, kept only if the
calibration shows a clean render at 33 dB or more and a planted one at 27 dB or less (stop rule 4 otherwise). OPEN-10: the DOM measurement runs in the
HyperFrames container right after the drawing (same page, same runtime) and the box rules and the pixel check in the encode container, so there is no new
container and no rule written twice.

**Choices where the spec left room, and where the code answered otherwise.**

- The measure step runs only for a render that draws: the host gives `hf_render.py` the flag `--measure` for every composed render and for no base-only one,
  and refuses a composed render that comes back without `boxes.json` (`container_wrote_no_file`). The spec runs it unconditionally; a base-only page has
  nothing drawn to measure and would pay a second Chrome pass for an empty list. The flag is not reachable from a verb's command line, and there is no flag
  to leave a composed render's gates out.
- Glyph rectangles are tested against the face box as well as element boxes (the spec tests only element boxes for the face and both kinds for 1560). A
  block's instance clips what it draws to its band, so a text spilling onto the face never makes an element box that reaches the face; the spec's own
  planted card (`hf:demo-cover`) would otherwise pass the DOM gate, and only the clipped, invisible picture would save it from the pixel gate. The risk is a
  false refusal for text that is clipped out of sight and sits on the face; the safe side is the stricter rule.
- The encode takes one flag more than the spec lists, `--proxy-sha256`, and checks the proxy's duration (`proxy_truncated`): the proxy is mounted
  read-write in the drawing container (it lives in the project folder), so it could be rewritten between the hash the host took and the pixel check, and a
  proxy shorter than the cuts is padded by the filter graph, never compared. The flags come all together or none (`Usage`, exit 2).
- The spec's exemption for frames where an entry with `may_cross_face: true` is on is not built: no block may cross the face on this engine (the engines file
  omits `cutaway` and `pip`, and an `hf:` block must have `may_cross_face: false`), and the encode container has no catalogue to read the property from.
  A parameter that nothing sets would be a way to switch the check off, so the check covers every frame of every kept range.
- The command of the pixel check ends on the last range's comparison (`-map [p<last>]`, the others to `nullsink`): a range's comparison ends when its trim
  reaches the range's end, so the last ends last. Mapping the first one made ffmpeg stop after it and left the later ranges half judged (found in the
  tests: 16 of 30 frames of range 2).
- `hf_measure.mjs` keeps the spec's FontFace replacement of `@font-face` rules for the top page and for each block page it serves, and asks the browser only
  for what the loopback server hands out (any other request is aborted and fails the measure). Not run here (it needs the image).
- The test files `test_hf_engine.py` and `test_hf_docker_live.py` changed more than the spec's list: the two tests of `gates_not_built` (the refusal is
  gone, so they became tests that the gates run in test mode and outside it) and the fake container of the host tests (it writes `boxes.json` and answers
  the encode stage with gate figures). `test_renderer_common.py` lists `_hf_gate` as a common module.

- Live run at 72305f9 and e1dfda3 (supervisor, Mac): every composed render refused `measure_failed player`, and the refusal's problems showed the player,
  `renderSeek` and `timelines.main` present and the document complete when the state was read, plus one failed request for `media/proxy.mp4`. Two changes
  follow, neither a measured cure until the next live run: (1) the ready wait is polled from node (`page.evaluate` every 100 ms up to `READY_TIMEOUT_MS`)
  and no longer by `waitForFunction`, whose polling runs on the page's own timers, which the runtime may freeze once up; the elapsed milliseconds are
  printed on success and carried in the refusal's state line, so the timeout can be set from a measurement (30 s is kept until then, not a measured
  figure); (2) the static server now answers a Range request properly (one range, `206` with `Content-Range`, a suffix range, `416` when out of bounds or not
  one range) and a failed request of resource type media with `net::ERR_ABORTED` is no longer a failure, because the media element cancels a range request
  and asks again. What that gives up: an abort of the media element that is never followed by a successful request is not refused by the request check;
  a video that never loads still shows as a page that never becomes ready, or as frames the pixel check compares with the base. Any other failed request,
  of any type, and any media failure other than an abort, still refuses.

- Live run at 1ad56f3: the page became ready and every composed render then refused `font_not_allowed`. Cause, read from the files: Chrome names a web font
  by the font file's own name table (ID 1), and the three static files declare "Inter Medium" (`inter-500.woff2`), "Inter ExtraBold" (`inter-800.woff2`) and
  "JetBrains Mono Medium" (`jetbrains-mono-500.woff2`), with "Inter" and "JetBrains Mono" only as the typographic family (ID 16). `hf_measure.mjs` now maps
  exactly those five names (the three file names and the two families) to the two allowed families, still requires `isCustomFont`, and writes the mapped
  family into `boxes.json`, so `_hf_gate` is unchanged. A test reads the three files' name tables with node and pins the names, and checks that every
  character of the demo text is in the fonts' cmap (no fallback glyph). A refusal now says, for each font that is not ours or not custom: its frame, the
  family (mapped, or `other`), `isCustomFont`, the glyph count and the element's tag, zone, class and id, in `problems`. The page's ready time
  (`ready_ms`, last in `boxes.json`) now reaches the drawing result as `measure_ready_ms` and the render result, to size `READY_TIMEOUT_MS` from a measurement.

- Live run at 2e1d5a6: a clean composed render was refused `face_pixels_changed range 0 frame 551 psnr 24.6`. Frame 551 is inside range 0 (a long range with the
  slow push-in), not at its edge. The cause found offline: the reference zoomed the 1080x1920 proxy itself with `zoompan` at a base of one, which snaps
  the window to whole pixels, and a renderer's zoom is smooth. Against the same zoom made at four times the size and brought down by area (a stand-in for a
  smooth zoom, on testsrc2 detail, a push-in of 2 percent over 120 frames, the face region), the base-of-one reference had a minimum of 26.3 dB and a median
  of 30.8; made at twice the size, as `compose_argv` zooms, 33.2 and 38.3 (executor, host ffmpeg, one run; the time for 120 frames on one thread went from
  0.4 to 1.6 s, about 45 s for 3419 frames, an estimate). `reference_graph` now brings a range that zooms to twice the output size before the zoom; an unzoomed
  range stays the proxy as it is (a round trip through twice the size costs it about 10 dB). The threshold is unchanged. Whether Chrome's own resampling
  (bilinear, not an ideal) keeps the real render above 30 dB is the next live run; if it does not, the render is refused as before. The refusal now carries the
  range's first and last output frame, the worst frame's offset in the range, how many frames are under the threshold, the median, the zoom at both ends of the
  range and what the timeline draws at the worst frame, in `problems`.

**Not verified.** That `hf_measure.mjs` runs: it is only syntax-checked (`node --check`) and read as text by `test_hf_measure_static.py`; that HyperFrames'
runtime reaches the `renderSeek` the script calls inside the loopback page, and that the runtime's `getVariables` reads `window.__hfVariables`
as the spike's measure script assumed; that the browser registers the page's `FontFace` objects before the first seek in the iframes; that a console error
of the page (a video decode warning, say) is not raised by this script on the real input; that the ProRes intermediate and the proxy agree to 33 dB in the
face region of a zoomed range on real content (the zoom here is Chrome's resampling against ffmpeg's `zoompan`); that the measure pass stays within the
1-2 minutes S2 measured with captions only; the memory of a second Chrome in the same container (V3c's page-cache question).

**Saving and loss (principle 13).** The pixel check costs one decode of the intermediate and one of the proxy, plus the base graph's cut and zoom of the
proxy, in one ffmpeg process with every thread pinned to one (seconds measured by the supervisor, recorded above when they come) and it covers what the DOM
cannot report. The measure step costs a second Chrome pass over every frame in the drawing container, only for a render that draws. What is given up:
a block that draws on the face by a means the page's DOM does not report, and does so by a change smaller than 30 dB over the whole face region of a range
in a frame, is not seen by the pixel check (a few pixels of a large region); the DOM gate covers boxes and text, and the contact sheet (C10) is the
maintainer's judgement for what neither sees.

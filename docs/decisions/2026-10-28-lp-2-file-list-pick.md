## 2026-10-28: after a list of files, an ordinal word opens the file in that place (LP-2, SPEC-LIST-PICK section 7, OPEN-LP-2)

- **Decision.** The maintainer approved OPEN-LP-2 on 2026-10-28 ("Sim"): after a file list, "o primeiro", "o segundo" and "o último" open the file in that position. `ops_file_read.take` reads the line with `_place`: a number form of S11 names a place only without a verb (unchanged); a line that is no number form is read by `list_pick.read`, and only an ordinal word or the word for last, with no verb, is decided by `list_pick.choose` against the places the list printed (1..k, so a position is the number the person read). The place goes on exactly as its number does (the right to read, the grant, the group `send-files`; a list for the trash or for a question opens that card or runs that question). No interpreter slot, plan item, card word or `turn_gate` number receives a position.
- **Not a pick of a file.** A value the list shows (a clock, a day, an account, a sender: the list shows names and folders; OPEN-LP-7), a verb with it ("lê o primeiro"), a place beyond the list, a longer request, and "a última" when the list printed fewer files than fit. The last case needed one new fact in the record: `_remember(..., whole=False)` says the list printed every file that fit; the list of `file-read` and, in the same package, the lists of `file-trash` and `file-ask` pass it (`count <= shown`), so "a última" means the last row printed on all three and is no pick when the list printed fewer files than fit.
- **The golden.** The one recorded row that moves is `file-list-number.near.04` ("o primeiro" after a file list): planning agent with one model call before, `file-list-number` with no model call now. It was re-recorded with `entry_corpus_build.py --re-record file-list-number.near.04 --cause "LIST-PICK, maintainer 2026-10-28"` (the guarded mode of L64H); the diff is the header's `changes` entry and that one row. The base corpus authored that row as a near-miss of `file-list-number`, so `test_every_authored_take_is_taken_and_every_near_miss_is_not` now excuses a near-miss only when a reviewed re-record named it in the header's `changes` (`authored_wrong`, with a vacuity test). The package `lp-2` appends four scenarios (`entry_ext/lp-2.*`): "o segundo" and "o último" open the second file through the bridge, "lê o primeiro" and "o das 15h" go on to the planning agent as before. "a última" was not used because LP-1's `lp-1.near.02` has a model text for that line.
- **Not done.** No catalog, prompt, protocol, enabling entry, limit or phrase key change; no value pick for files; no model call, no lab run, the fingerprint is unchanged.

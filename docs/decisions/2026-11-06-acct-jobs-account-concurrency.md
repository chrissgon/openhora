## 2026-11-06: a concurrency limit per account in the lab's shared lock (ACCT-JOBS; infrastructure, no measurement change, no lab run)

The maintainer's request, 2026-11-06 (verbatim): "Para evitar erros 429, rode os jobs em contas intercaladas, tipo 20 testes no claude e 20 no openrouter". validate: allow english-only -- the maintainer's words, quoted
In English: to avoid 429 errors, run the jobs on interleaved accounts, for example 20 tests on Claude and 20 on OpenRouter.

- **Kind: infrastructure** (locks and pacing). No file of the fingerprint changed (`evals/execution.py`, `evals/run_attempts.py`, `evals/eval_run.py`, `evals/eval_status.py` and the gate file are not in it), so `python3 evals/eval_status.py measurement` was not run, `measurement_sha256` is unchanged, and there is no epoch, no version raise and no skill bump. No lab run is asked for.
- **D1. The key is `account_jobs`, `{adapter folder name: whole number 1..64}`.** A model reaches its account through its adapter, the name every call already carries as `account["key"]` and that names the pause file, so the account that is paused is the account that is limited. An adapter the key does not list has no limit but the total. Rejected: keying on `pass_env` (the same model switches variables on web runs and a model with no route has none, so one account would become two keys or none), and a new `account` field on the model entry (it enters `MODEL_ENTRY_KEYS`, a closed list that many fixtures build; it replaces this rule the day one adapter serves two provider accounts). Known limit: two accounts behind one adapter would share one limit, which errs toward fewer calls at once.
- **D2. Lock order: web, then account, then total**, released in reverse, one `Slots` per thread at a time (entering a second raises). One fixed order over the lock classes and at most one place of each class means no circular wait, in one process or across processes. Rejected: total before account (calls queued on one account would each hold a total place and starve the other account, the failure this change exists to avoid), and account before web (a web run waiting for its model's web places would hold an account place). A local model's run takes no account place, because its calls reach the person's own server. Places are still polled with no queue: no deadlock, no fairness, as before.
- **D7. Committed value `{"claude-code": 7, "agents-dir": 7}`, `total_jobs` stays 14.** Rejected: leaving the key absent on main and setting it locally (it keeps today's behaviour but leaves the request unmet in the committed lab configuration, and a local edit of a committed file in the live checkout leaves the tree dirty).
- **Principle 12 and 13.** The change reaches no measured run, no skill hash and no fingerprinted file, so it costs no battery. The cost: an event that uses only one account gets half the machine (7 calls at a time instead of 14 across processes). The gain: no account carries more than half the machine, and a 429 costs a retry with back-off or an adapter failure, so fewer 429s also save time and money. The cost is bounded and visible, the gain is the maintainer's explicit request, so the stricter rule wins.
- **OPEN-1 is closed as: no change of `total_jobs` in this pull request.** The 40 total with 20 + 20 per account is set locally on the maintainer's machine at run time. Committing `total_jobs: 40` would also need the sentence of `evals/README.md` on Docker's default address pools (about 31 bridge networks, enough for 14 runs at once) to say that 40 needs the larger pools this machine was given; that stays the maintainer's call.
- **Not verified:** whether 7 calls per account removes the 429s. No rate limit was read and no model was called.

## 2026-11-07: the catalogue contract and the oh: blocks (V3b0; no measurement change, no skill changed, no lab run)

- The ffmpeg engine's seven templates are the `oh:` blocks, byte for byte: `providers/renderer/blocks/oh/<name>/renderat.html`, each with
  a `block.json` (kind, preset, band, `may_cross_face`, licence, source, `use_when`, typed parameters, samples, natural duration,
  implementations). A test holds each page's sha256 equal to the old pin, and a render of the same inputs before and after gives the same
  bytes.
- Folders carry the namespace (`blocks/<namespace>/<name>/`), one level more than section 3 of
  `2026-11-07-v0-short-video-hyperframes.md` wrote, so that an `hf:` port can never collide with an `oh:` block of the same name.
- `block.json` names one implementation file per drawing runtime (`renderat`, `gsap`); two runtimes may name the same file, so V3b's
  measurement of one `renderAt` file for both runtimes needs no schema change. An `hf:` allowlist entry has the same schema plus `tier`,
  `commit`, `notice` and `files`.
- An engine (`blocks/engines/<engine>.json`) runs a list of runtimes and names its block per preset. It draws a block only through a
  runtime it runs; any other is refused as `block_not_on_engine`, with the engine's own block for the preset as the field (F7, F8, G14).
- `blocks/pins.json` names every block file, engines file and the allowlist by sha256. A render or a storyboard copies the pinned files
  into the job's read-only folder, loads them from the copy, and passes the sha256 of the copied pins to the container, which checks it
  again; the result carries `blocks_sha256` and the sha256 of each drawn block (G9). The blocks leave the image: a block change rebuilds
  nothing. Saving: no image rebuild per block, and the approval can bind the exact blocks. Loss: none in safety, since the files are
  hashed twice on the copy and never read from the live checkout during a render.
- The renderer-side checker (VD15) checks a block's parameters against its `block.json` or allowlist entry, with the vocabulary's types
  plus `number`. It runs in every render for every beat, on every sample in a test, and on the host as `ffmpeg.py block-params`: VD4's
  container rule covers what reads a recording, a transcript or a post, and a block's parameters typed in the review are none of these.
- The catalogue (`blocks/catalogue.json`) is generated by `ffmpeg.py pin-blocks --confirmed` from the pinned files, our fields only
  (VD13); a test holds it equal to the generator, and an entry without a sample is refused. `pin-templates` is gone.
- Correction to `2026-11-07-v0-short-video-hyperframes.md`, section 1, C9: the repository's licence is MIT (`LICENSE`), not Apache-2.0;
  the `oh:` blocks carry `MIT`.
- The image tag changes (`_blocks.py` joined the manifest, the templates left it, `renderer-presets.json` lost its `template` keys).

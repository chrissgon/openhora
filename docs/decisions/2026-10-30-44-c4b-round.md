## 2026-10-30: the dispatcher's round and the releases a mode makes move to ops_round (44-C4b; SPEC-44C4, OPEN-C1 B, OPEN-C2, OPEN-C4-1 to OPEN-C4-5)

**Decision.** What a dispatcher round reads before it decides, what a release starts, and the tick of the handlers leave `runtime/ops.py` for the new `runtime/ops_round.py`. 20 names: `_release`, `_approved_plan`, `_brief_delivery`, `_after_release`, `_reroute`, `_not_rerouted_decision`, `_not_rerouted`, `_backlog_subtasks`, `DISPATCH_BUDGET`, `STOPPING_FAILURES`, `STOPPING_REASONS`, `_proven_on`, `_snapshot`, `_mode_releases`, `_deliveries_acceptance`, `_stops_the_round`, `_configuration_moved`, `_credential_stop`, `_image_stop` and `_ticks` (344 code lines). With 44-C4a this is the whole closure of the run and the round that `ops_runs` read in `ops.py`: C4 moved 38 names in all. The bodies are byte for byte what they were. Two lines differ from the base: `_snapshot`'s route (`ops_models.route(` where `ops.py` called its `_route`, the same call, as `_router_call` has done since 44-C3) and `_ticks`' call of `handler_call`, which goes through the seam of OPEN-C1 B, `ops_facade.function("handler_call")`. `ops.py` re-exports every moved name after the marker, so `dir(ops)` is the base's plus the module name `ops_round`.

**What the callers do now.** `ops_runs.dispatch`, `_round` and `_pass` reach the round through `_round_module()`, `importlib.import_module("ops_round")` at call time (the local name is `rounds`): `ops_round` imports `ops_runs` for the held record, the children and the pieces of a run, so `ops_runs` cannot import it back. It is a `cycle:` row (`ops_runs -> ops_round`) in `test_import_breakers.py`. The edge `ops_runs -> ops` is gone, with its row and the constant `CYCLE_OPS`: since this change only `dispatcher` (the entry) and `ops_facade` (the seam) load `ops` at call time, and `test_ops_facade.py` pins exactly that pair. `ops.py`'s `release` calls `ops_round._release` and its `poll` calls `ops_round._snapshot`, `_mode_releases` and `_brief_delivery`.

**`handler_call` stays.** It is an operation of the table, so under OPEN-C1 B it does not move (OPEN-C4-1); `_ticks` reaches it through the seam, which reads `ops.handler_call` at call time, so a patch on it keeps reaching the tick. `_handler_verbs` and `HANDLER_TIMEOUT`, read only by `handler_call`, stay with it.

**Principle 11.** Nothing on the path where an effect is approved or executed moved (`approve`, `_approve_effect`, `_execute_effect`, the cards, the grants, the gate of a run in `ops_task_run`). A release is not an approval; the lock a release holds when it routes a brief again (`core._route_lock`) and the refusal of a blocked change set are in the same bodies, unchanged. The probe that records every pending decision, effect document and recovered payload (the gate capture of the spec) gave the same records before and after the move.

**Tests re-pointed.** Five patched `ops.<name>` for a name the moved code reads from `ops_round` now: `_snapshot` (`test_parallel_runs.py`), `_approved_plan` (`test_project_language.py`), `_image_stop` and `_credential_stop` (`test_parallel_processes.py`, including the child script of the SIGINT test, and `test_step_tasks.py`). Two guard sets changed with the move, each named in the PR for the reviewer: `OTHER_NAMES_OF_THE_SAME_WORDS` in `test_turn_gate_refresh.py` (`ops_round.py` defines `_snapshot`) and `EXPECTED_IMPORTERS` in `test_ops_facade.py` (`ops_runs` left the set).

**Budgets.** `LAZY_CALLS_BUDGET` 59 and `LAZY_EDGES_BUDGET` 48 are unchanged (one edge out, one in), `PLAIN_DEBT_BUDGET` 0. `OPS_PY_BUDGET` 1,772 to 1,428 (344 code lines moved; headroom 32 as before). `ops_round.py` is 422 lines and `ops_runs.py` 1,021, both under the 1,200 of a sibling.

**Alternatives rejected.** Moving `handler_call` with `_ticks` (an operation does not move). Moving `ops_runs`' own round functions (`dispatch`, `_round`, `_pass`) into `ops_round` so that no edge goes back (OPEN-C4-3: it re-points the patches on `ops_runs.spawn`, `SPAWNED` and `STOPPING` and the pinned `_pass`; a later consolidation package can do it).

**Not changed.** No rule, phrase, policy, approval, limit or card hash; no new behaviour. The entry golden is untouched and replays identically.

## 2026-10-28: the text of one e-mail on a phone, behind its own group (CB-3, SPEC-CATALOG-BATCH 6.3, OPEN-CB-5 as the maintainer decided it)

- **What.** The class R operation `mail-read` (`runtime/ops_mail_read.py`, `natural.order` 100, catalog version 2, so a line reaches it only after the flip; the served catalog is byte for byte the newest entry's): one message of the newest mail snapshot by its number or by words, the snapshot's own cleaned body, 1,500 characters on a phone. Group `read-mail-body`: in no default policy, never on the MCP mode, turned on only by `accept-config --widen`; `project_config` refuses a messaging policy that lists it without `ask-mail`. `ask-mail` is neither widened nor re-worded (pinned by a test).
- **The decision.** The maintainer, 2026-10-27, "Nova ampliacao no terminal (Recomendado)": reading a whole message on the phone is a new widening, so it is a group of its own and not a change to what `ask-mail` grants.
- **Deviation from the spec (by number never refreshes).** The spec said to read each source again once when older than ten minutes before choosing. A refresh renumbers the snapshot, so "read 2" after a list could show another message than the one listed; a line that names a number therefore never refreshes (the rule `ops_natural_mail._may_refresh` already holds for the writes), and a line that names words refreshes each old box once under the line's budget. The snapshot is still refused after 26 hours.
- **Other choices where the spec left one.** The page route is `POST /projects/{p}/mail/read` (a POST so that words are never in a URL; `test_service` wants a route for every row that lists the page). Words that leave nothing to look for, with no day, ask which message (`MR_ASK`), they never list everything. A day the time engine cannot read, or an index entry with no `received`, is told with its own sentence (`MR_DAY_UNREAD`): never guessed. Because this is the first row of catalog version 2 (a class and no row of the table), a few assertions of `test_registry_rows.py` and `test_natural_table.py` were generalised, and the lists the tests keep by hand take `mail-read` from `runtime/tests/expected/cb-3.json`; the phrase keys are in `runtime/phrases_parts/cb-3.*.json`.
- **Not done, and not changed.** `interpreter.py`, the prompt, the protocol, the enabling entry, the entry golden, `turn_gate.py` and `gated_ops.json`; no model call, no lab run, the fingerprint is unchanged. The v2 catalog (a measurement) is CB-9's.
- **Review round (CB-3, Opus review "merge after fixes", all four deviations accepted).** (1) A box whose read failed was skipped in silence, so "read 2" could show Outlook's 2 while Gmail's was unreadable: by number the reply now names the unreadable box and shows nothing (unless an account or a `<source>#<n>` narrowed the search to boxes that were read); by words a single hit is listed with a note and never shown. (2) With three holders the sentence said "Two" and suggested a form no line can read: every holder is named with the real count, and "read 3 from Gmail" is suggested only for a message no other box of that account holds; otherwise the page (a phone) or `--message <source>#<n>` (terminal and page). (3) `test_widening_fuzz`: the companion is added only on `messaging`, 500 rounds again. (4) Vacuity cases that plant "pick the first holder", a skipped box and neutral storage off; a missing stored word counts as a leak. (5) `MR_DAY_UNREAD` for a day the engine cannot read (`NW_MAIL_BY_DATE` says "yet", which is false here). (6) The old-snapshot note after a failed refresh by words. The service word must name exactly one account and agree with the line, as `ops_file_read.line_target` has it.
- **Known limit (finding 7, not fixed).** A list, or the which-box sentence, is not pinned to a snapshot version: a refresh between it and "read 3 from Gmail" can make the number name another message. Every reference of the platform has this property; a pin would need the plan or the list to carry a version.

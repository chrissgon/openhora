## 2026-11-04: An event named by its words is searched in fresh snapshots, and the by-name list numbers its rows by position (AF-3 EVENT-FRESH, acceptance row 38; no model call, no provider call, no lab run)

**The fault.** The search of an event by its name (`runtime/event_lookup.py`) read each calendar source's newest snapshot, up to 26 hours old, and refreshed it only on a miss. An event added in the calendar's own app after the last read was no candidate; an event removed through a card still was; when something old fit, the miss refresh never ran. Two sources number their snapshots from 1 each, so a list of matching rows could print two "1."s and the answer "1" matched both (`EV_LIST_AGAIN`, a dead end).

**What was built.** (1) `ops_items.refresh_for_line` is `_refresh_failed` for a caller outside the module: the same 10-minute age limit, the same mark of a changed calendar (`mark_changed`), the same budget of one read for a source in a line and the same closed stderr line. `event_lookup._found` calls it for every calendar source before the first search when the sender may read a snapshot; a failed read leaves the old snapshot, as in the items list; the read of a miss stays and is skipped for a source already read in the line. (2) A by-name list in which two rows would print the same number (two sources, each numbering its snapshot from 1) prints positions 1 to k (`_list`, `_clash`), records `positional` with the list, and `_taken`, `_pick` and `_pick_reply` read the number of such a record as a position; every other list keeps the snapshot's numbers; the numbered line handed to the family carries the snapshot number kept at that place (`_number_form` also returns the head and the rest of its line), so the card is bound to the snapshot's own number. (3) `EV_POS_CANCEL_HOW` and `EV_POS_CHANGE_HOW`, used only for a positional list (the other lists keep `EV_MANY_*_HOW`), ask for "o número da lista" (`runtime/phrases_parts/aceite-fix-3.*`).

**OPEN-2, positional only on a clash (the supervisor's decision, replacing the recommendation of full positional numbering).** Only a list that would print a number twice is numbered by position; after it expires, a late "evento 1" means the snapshot's entry 1, and its card shows which event and waits for approval. Every list without a clash, the items list and the lists of the platform's own events keep their numbers, so no existing golden row moves.

**Cost.** One calendar read for each source on a by-name line when its snapshot is older than 10 minutes or marked changed; none otherwise; no model call.

**Principle 11.** No approval check and no card hash is touched: the card a number opens is the card the numbered form opens, approved by its own hash.

## 2026-11-28: An agent's profile, written by the person and proposed by the agent (ac1; plan `docs/architecture/agent-company-plan-2026-11-27.md`, section 4.1; issue #990)

**Status.** Built by package AC1 on the wave-2 branch. The question it rests on, who writes a profile, was decided by the maintainer on 2026-11-27 and 2026-11-28 and is recorded as AC-D18 in `docs/decisions/2026-11-28-w0-decisions-backlog-wave-0.md`; this entry does not record it again. It builds AC-D1 (a persona per agent).

**Context.** AC-D1 gives each agent a persona. AC-D18 says the person alone writes it, an agent may propose a change, and the person accepts on the page or in the terminal. The file shapes only the conversation lane's replies. A skill run must never see it, and a run must never be able to change it, because a profile that a run could write would steer every later reply (limit L40 for the standing instructions has the same reason).

**Decision.**
- AC1-D1. One file per agent, `docs/workbench/agents/<agent>.md` (`path_rule.AGENTS_DIR`), where `<agent>` is a key of `area_agents` and a name of lower-case letters, digits and single hyphens, at most 64 characters. The slot is the person's in `contracts/project-layout.md`; no skill declares it.
- AC1-D2. Limit L40 is extended, not replaced: the path rule calls the folder and anything under it `other` under every spelling a disk folds (as the flows folder), so no run returns it, the mirror never sends it and no change set carries it; `workcopy._never` keeps it out of every copy; `_protected_alias` follows a link to the folder. The same checks as the standing instructions guard the file (UTF-8, a regular file, not a link, inside the project, a credential scan, no invisible character, no separator line, no words of a block's own marker).
- AC1-D3. The cap is 2,000 characters, and 8 KiB are read at most. The profile rides on every lane turn beside the standing instructions (4,000), so it is kept to about 500 tokens (`Assumption: about 4 characters per token`). This is a choice of this package, not of the maintainer; a change of the cap is one constant.
- AC1-D4. A profile reaches the conversation lane only, as a block marked by a nonce, between two marker lines, with the facts code added from the configuration (agent, area, skills, colleagues). The block is a function (`ops_profiles.lane_block`); no run, step or lab case calls it, and AC3 is its first caller. A test holds that the lab and `evals/` never name it.
- AC1-D5. The person writes with `profile-set` (a compare-and-set on the file's sha256) from the terminal or the page, the channels of `operations.PROFILE_CHANNELS`, and no channel policy widens them yet. An agent, or an MCP client, calls `profile-propose`, which writes nothing to the project. The person accepts with `profile-accept`, naming the proposal by its sha256, or drops it with `profile-reject`. The checks run at the proposal and again at the acceptance; a profile that changed after the proposal was made is not overwritten, and the proposal is kept.
- AC1-D6. The proposal is kept in `<data_dir>/profile-proposals/<agent>.json`, one per agent, outside the project and every repository, and not in the store. Principle 13: this saves a store migration that would race the numbers of other packages in the same wave; it loses that a proposal is not in the store's backup and goes with `data_dir`, which loses only a draft nobody accepted.
- AC1-D7. The five operations are class G internal rows (`runtime/gated_ops.json`), never served in words in v1, so the served catalog does not change. Routes for the office page are `/projects/{p}/agents/{name}/profile` and its `propose`, `accept` and `reject`; the page's buttons wait for the office package.
- AC1-D8. The `area` key of the facts is reported as none until AC8 adds it to the configuration.

**What this does not do.** It does not change the conversation lane (AC3), the office page, a conversation per agent (AC2), the agent channel or the group `agent-chains` (AC7). It touches no skill and no fingerprinted file, so no bump and no lab run.

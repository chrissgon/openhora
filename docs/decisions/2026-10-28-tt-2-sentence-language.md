## 2026-10-28: the language of the fixed sentences, per sender or per channel (TT-2; no model call, no provider call, no lab run, fingerprint unchanged)

The maintainer decided (2026-10-27, option C, answering OPEN-TT-1 of SPEC-TIME-TABLES-ES-FR-DE-IT): the fixed sentences the runtime says to a person (cards, confirmations, readings, refusals, the plan question, reminders, list headers) follow the project's `language`, adjustable per channel or per person through a profile key; what a model writes follows the writer's language and is a separate, measured prompt change (backlog WRITER-LANGUAGE); no es/fr/de/it phrase table is written in v3 (backlog PHRASES-ON-DEMAND).

- **The key.** A profile of `policies` written as an object may carry `sentence_language`, one of the tags of the phrase table (`en`, `pt-BR`); any other value, or a non-string, is a `ConfigError` naming the two. It is not a group, grants nothing, is no widening and is never read by `language.effective`, a run's prompt, a plan line or a router: artifacts keep the one source (the decision of 2026-10-16). No profile of any default sets it, and a record holds it only when the file does, so a file without it loads and answers byte for byte as before.
- **The resolution and the scope.** `phrases.sentence_tag(cfg, channel, sender)`: the sender's profile (messaging), else the channel's profile (page, mcp, messaging), else the project's `language`; the terminal and the conversation's own shell are never narrowed. `phrases.scope(tag)` is a thread-local `with` block inside which `phrases.tag` answers the scoped tag when the table has it (the table is HOT-2's core plus the parts: the scope only reads its keys). It is opened in `Bridge.sentences_for` (the handling of an update, a card sent to a chat, a reminder delivered, the "N more waiting" and unread notices, a waiting line started again or told it was dropped, the stop notice), `Bridge.inherit` hands it to the job a line starts, and `ops_say.say` opens it for a page or MCP line; every opening is a `with` block and the previous scope is restored on every exit. Only the accepted configuration is read. A path that opens no scope says the project's language: the restrictive default.
- **What it does not do.** No phrase column; no change to a prompt or to anything a model is shown; the language of the e-mail composer, the router and the interpreter is still the project's, so a model-written mail does not yet follow the writer's. A decision's own text, names, commands, ids, a stored card's canonical English body and the text of an `OpsError` are not translated, as before. The reply the conversation stores for a line is the one said, in the sender's language.
- **Proof.** `runtime/tests/test_sentence_language.py` (the schema and its refusals; the resolution; the scope, its nesting, its restore on an exception, its thread-locality and its inheritance by a job; a pt-BR project where the desk and a guest say `en` and the owner and the staff keep pt-BR: refusal, greeting, reminder and its delivery at tick time, card kind words, and a key equal to the project's language changing nothing; the plan question against its English form on the real operations layer; the page, the MCP mode and the terminal; the artifacts' language facts unchanged with the key set; a scan that only phrases, project_config, the bridge, messaging_remind and ops_say read the key), each with a vacuity case that fails on a planted wrong result. The entry replay package `tt-2` (`entry_ext/tt-2.scenarios.jsonl`, four rows, the pre-state `two_languages` and the sender `asker_en` in one block of `entry_kit.py`): the owner's "oi" and agenda line in pt-BR, the second sender's in en; the base corpus and golden are byte for byte what they were.
- **Noticed, not changed.** In a pt-BR project the refusal of `/remind` for a profile without the group `reminders` reaches the phone as the generic failure sentence and not as the plain refusal sentence the other commands get (`/approve` does); it is the same without this package, so it is left for its own change.

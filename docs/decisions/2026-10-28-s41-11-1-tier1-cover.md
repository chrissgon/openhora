## 2026-10-28: the tier-1 cover set and its gap list (S41-11 PR 1, SPEC-41-11-ADDENDUM; no model call, no lab run, fingerprint unchanged)

S41-11 deletes the code claimers that take a line before any model. Before that, the lines they take today are written down as items of the corpus, so that M41-5 can measure the interpreter on them, and the requests that have no operation to go to are listed for the maintainer. This is PR 1 of the three the addendum defines (PR 2a claimers out, PR 2b dead tables); it deletes nothing and changes no behaviour of the product.

**Decided by the supervisor, by recommendation (2026-10-28):** A11-4, PR 1 reuses `evals/interpreter/dev-relabelled.jsonl` for the three corpora and builds only the lines no corpus holds. **Accepted by the maintainer (2026-10-28, "Aceito (Recomendado)"):** A11-2 (a brake said in words goes through the interpreter; typed commands and buttons stay; during an outage the brake is typed), A11-3 (page, terminal, mcp and chat lines that tier 1 took go to the planning agent), A11-7 (a sender with only a read group loses reads in words; typed commands stay). They bind PR 2a; this PR only measures and lists.

What was built:
- `python3 scripts/interpreter_corpus.py tier1-cover` (with `--check`), whose builder is a new `scripts/interpreter_corpus_tier1.py`. It runs today's claimers offline (`natural.match`, `natural_writes.candidate`, `natural.claim`, in the order of the turn) over 1,568 distinct lines: the three corpora, every entry scenario whose recorded trace holds one of the six rows S41-11 retires, and the form lines held as literals by `test_natural_table.py` and `test_commands_in_words.py`. The rule has seven numbered points, in the module's text and in `evals/interpreter/README.md`, section "The tier-1 cover set". A line is an item when the served catalog lists its operation, a gap when it lists it in `refused` or not at all; the gold is the operation the claimer named, with the integer slot only when it is the operation's whole slot set, else scope `op`; no span is invented (every one is a substring, a test proves it).
- `evals/interpreter/tier1-cover-v1.jsonl` (199 items, author `relabel`, ids `dev-<lang>-4NNNN`) and `tier1-cover-gaps.json` (the accounting per source and the gap list). 1,258 lines are taken: 58 are gaps, 1,001 are covered by `dev-relabelled.jsonl`, 199 are added.
- `scripts/interpreter_corpus_format.py`: the relabelled author's id range grows from 10000-39999 to 10000-49999 and gains the base 40000 for this source (the message of the check changes with it).
- `scripts/tests/test_layer_map.py`: one row lets `scripts/interpreter_corpus_tier1.py` read `runtime/natural.py`, `natural_time.py` and `natural_writes.py` by path, as `scripts/registry_build.py` does; a layer never reads it. PR 2a deletes the script with the claimers.
- `runtime/tests/test_tier1_cover.py` (15 tests, a vacuity case for each guard).

**The gap list, for the maintainer's decision (it blocks PR 2).** 13 operations, 58 lines (29 English, 29 pt-BR), every one in the served `refused` list of catalog version 2, none absent. The D operations lose little: `approve` (17 lines) in words only sends the card again today, and the interpreter's `_decided` runs `reject` (13) and `release` (6) by the number written; `go-ahead` has 2. The widening G operations become "type the command": `give-consent` (3), `config` (3), `accept-config` (2), `deps` (2), `routine-approve` (2), `set-mode` (2), `set-model` (2), `source-add` (2), `source-import` (2). Each is accepted by the maintainer, or the catalog gains the operation (a dated entry and its own measurement).

**M41-5 is not run here, and cannot run as the spec wrote it.** It calls a model on both routes (about 3,086 calls a route: 1,344 + 199 items, 2 runs) and waits for the maintainer's "pode". And the pipeline's stage 3 calls `natural.match` as the product does today, so it decides 133 of the 199 added items before the model; the 1,344 relabelled items are untouched. M41-5 asks what the model does with exactly those lines, so it runs with stage 3 off, switched in the maintainer's script with no edit of the repository (`pipeline._tier1 = lambda line: None`, in the README). The decision for the supervisor: that run-time switch (the events' harness hash does not show it; their `stages` line does: no `tier1`), or a PR that adds a harness option (it changes `harness_sha256`, so the epochs of the earlier events) before M41-5. By recommendation the switch, because PR 2a deletes the stage and the option would live for one measurement.

What it does not prove (principle 10): the claimers run with the interpreter off for the sender (a repeating line is claimed by the closed form, as before catalog 2); `help-in-words` is read without the greeting exception of a sender who may talk; an entry scenario's line is read with no frame whatever its prestate; 4 lines ("remind me at ...") are labelled `mixed` because both language tables claim them (per-language bounds leave them out, the overall bounds count them); the reminder items of `dev-relabelled.jsonl` (scope time) judge the reading of the time, not the choice of the `remind` operation, and the 53 added reminder-form items judge the operation alone. After PR 2a the builder is gone and the two files are frozen data: `test_the_committed_files_are_what_the_claimers_give_byte_for_byte` and the planted-claimer cases go with the claimers.

## 2026-10-27: One file per decision entry (DECISIONS-FILES; the maintainer's go, 2026-10-27)

Every package appended its entry at the end of `docs/decisions.md` (2,827 lines at the base of this package), so each merge left every other open pull request in conflict on that file, and each conflict cost another hook run and another 20-30 minute CI cycle (about ten times on 2026-10-27).

- **The change.** New entries are files in `docs/decisions/`, named `YYYY-MM-DD-<package-id>-<slug>.md`, with the entry's usual first line `## YYYY-MM-DD: <title> (...)`, the date equal to the name's. A merged file is never edited; a correction is a new file that names the one it corrects. `docs/decisions/README.md` states the rules. `docs/decisions.md` is closed, not moved: a note at its top says so, and no entry was moved or rewritten, so the citations of it (about 50 files) stay true. The note is at the top so that open pull requests, which append at the end, do not conflict with it.
- **Checks.** `scripts/validate.py` has a check, `decision-files` (an error): a file of the folder other than `README.md` whose name does not match `^\d{4}-\d{2}-\d{2}-[a-z0-9]+(-[a-z0-9]+)*\.md$`, or whose first line does not start with `## <the date of its name>: `. The `english-only` and `private-term` checks already read every tracked text file, this folder included (a test pins the first). `python3 evals/eval_status.py measurement` now tells the maintainer to put its entry in a new file of the folder and suggests the file name (`<date>-measurement-<kind>.md`); its output keys are unchanged. `AGENTS.md` (the `docs/` row and the sentence on the entry that `measurement` prints) names the folder.
- **The selector and the workflows.** Nothing special-cased `docs/decisions.md` in code: `scripts/select_tests.py` leaves a document outside the named areas (`docs/architecture/` is the only part of `docs/` in them) to the guards alone, and the `changes` step of `.github/workflows/checks.yml` and `nightly.yml` match paths that `docs/` is not part of. So `docs/decisions/*.md` behaves as `docs/decisions.md` did, and a test for each pins it (`test_select_tests.py`, `test_checks_wiring.py`). `scripts/test_slots.py` only cites an entry in a comment.
- **Not touched.** `skills/`, `agents/`, `templates/`, `contracts/` and every file of the measurement fingerprint (fingerprint unchanged). `skills/core-skill-creator/SKILL.md` and its authoring guide still say `docs/decisions.md`; principle 12 applies a new convention to new or changed skills, so they change with that skill's next change. Comments that cite an existing entry stay true.
- **Principle 13.** Saved: one CI cycle per open pull request for each merge. Safety given up: none; the record stays append-only in spirit, since an entry file is never rewritten, and a check refuses a misnamed file.

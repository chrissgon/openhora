## 2026-10-28: the evidence-line tests take a fixture source of the shape they test, not the first file of the glob (BATCH-KEEPER fix of a red base; no model call, no lab run, fingerprint unchanged)

**What broke.** On `feature/delegation-platform` from #633 on (the first full test of `asst-answer`, lab evidence committed byte for byte), 16 tests of `evals/tests/test_local_model_event.py` and 17 of `evals/tests/test_evidence_lines.py` failed, most with `TypeError: list indices must be integers or slices, not str`, and the nightly failed with them. Cause: both files build their fixtures from `COMMITTED[0]`, the first committed lab-evidence file in sorted order, and read its event line as the OLD header shape (`models` is `{tier: id}` with one gate). Until #633 that file was `biz-icp-positioning`'s (old shape). `skills/asst-answer/...` sorts first and its test event carries the LIST header (`models` is a list of ids, `adapters` keyed by model id, a gate per model), so `as_list_shape` indexed a list by a tier name. Each merge was green alone: #633's pull request changed an evidence file, which no test names and the selection does not map to `evals/tests`, so those tests did not run on it (checked: removing the asst-answer evidence directory from the tip makes both files pass again, 112 tests).

**What changed (tests only).** `evals/tests/test_evidence_lines.py` keeps three lists: `ALL_COMMITTED`, `COMMITTED` (the files whose header is the old shape; every fixture that reads a tier-shaped header keeps using it) and `LIST_COMMITTED`. The two tests that mean every committed file (`test_the_repository_has_committed_evidence_to_test_against` and `test_every_committed_file_is_valid_by_its_own_event_line_with_no_gate_file`) read `ALL_COMMITTED`, so a file of either shape is still checked. `as_list_shape` returns a list-header event unchanged. No evidence file was touched (a committed evidence file is never edited), and no reader code changed: `evals/evidence_lines.py` reads both shapes correctly, as the test over every file shows.

**The test that would have caught it.** Three tests at the end of `test_evidence_lines.py`: the two shapes partition the committed files and each fixture source has its shape; a file of either shape gives a valid list-header fixture; and a vacuity case where the builder as it was (indexing `models` by tier) raises `TypeError` on the list-header file of the repository while the new one returns it unchanged. A new committed file of either shape now cannot change which fixture the tests use.

**Not done, for the maintainer.** The selector does not map `skills/*/evals/evidence/*.jsonl` to `evals/tests`, which is why the pull request of #633 was green: a change to an evidence file reaches the tests that read the committed evidence only in the whole-suite runs. A rule for it (a changed evidence file selects `evals/tests/test_evidence_lines.py`, `test_local_model_event.py` and the status tests) would close that, at the cost of running them on each evidence commit; not added here, since the red base comes first.

Principle 13: the saving is a base that is green again with no change to the evidence or to the reader; the loss is none (every committed file is still read by the two tests that mean all of them).

**The list on screen (MAIL-ASK-BINDING) and what the review rounds added.** `ops_natural.run` binds `message=<source>#<n>` for `mail-ask` as for `mail-read` (`item_refs.listed_source`): right after a reply that listed ONE of two or more mail boxes, a number with no box in the line means that box, so the plan's hash carries it and a number that only ANOTHER box holds is never read. The list is remembered with the ids of its messages, so "the same list" means the same ids in the same order, not the same snapshot version: a refresh that only changes a read flag makes a new version and moves nothing (probed: it made the first version of the refusal answer "moved" falsely). If the box now numbers the messages differently, the list is asked for again (`ML_LIST_MOVED`) on EVERY line since the list inside the ten minutes, until a new list, for `mail-read` too and also when the line names the listed box. A `match` that is one run of digits is the number. A number outside 1 to 9999 is asked again before any plan. Words and a pasted list line are matched when the yes is given, not at the question: they pin nothing, so a refresh between the two is not a stop; the yes reads the snapshot again if it is older than ten minutes and reads the ONE message that matches then (only a message that matches those words is read, and the footer names it); several matches are listed and nothing runs. Tests: `runtime/tests/test_mail_ask_binding.py` (a planted old rule fails them).

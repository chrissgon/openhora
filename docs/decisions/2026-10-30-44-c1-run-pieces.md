## 2026-10-30: the pieces of a run move from ops.py to ops_runs.py (44-C1; SPEC-44C, OPEN-C1 B, OPEN-C4)

**Decision.** Fifteen names that five siblings reached in `ops.py` at call time move to `runtime/ops_runs.py`, byte for byte (the body, the docstring and the decorator; the only line that differs is the one where `_agents_of_the_day` reaches `ops_ask.run_owners`): `NOTE_LIMIT` and `_note` (the reason recorded on a run), `HANDED_LINE`, `EDITED_LINE` and `task_prompt` (what enters a run), `_count`, `_skill_loaded` and `_reported_usage` (what comes back), `_key_in_environment` (the runtime's own key around a run), `code_task` and `_push_after_run`, `PER_RUN_USD`, `_midnight_utc`, `_budget` and `_agents_of_the_day` (the spend limit of a run and the day's caps). 156 code lines leave `ops.py` (2,655 to 2,499).

**What the callers do now.** `ops_ask`, `ops_file_ask`, `ops_research`, `ops_contained` and `ops_cancel` read `ops_runs.<name>` through a top-level import (`ops_runs` reaches none of them through its own top-level imports); `ops_contained` reads `ops_models.route` where it read `ops._route`, which only returned that call; `_route` stays in `ops.py`. The callers left in `ops.py` (`_run_body`, `_router_call`, `_snapshot`, `_run_start`) call `ops_runs.<name>` too, so that one production binding exists for each name and a patch target cannot be half-reached; `ops.py` re-exports the fifteen names in a sorted block after the marker, for the shells and the tests. No test patches any of the fifteen on `ops`. `ops_runs` replaces its own `_ops()` uses for `_agents_of_the_day`, `_note`, `code_task` and `_push_after_run` with local calls, and keeps `_ops()` for the run body and the round (44-C4).

**The one new edge.** `_agents_of_the_day` calls `ops_ask.run_owners`, and `ops_ask` imports `ops_runs`, so `ops_runs` imports `ops_ask` inside the function, with a `cycle:` row in `ALLOWED_LAZY`. The edges to `ops` fall from 14 to 9 (on the base after 44-B 3b: 68 calls, 56 edges, 1 debt; after this package 64 calls, 52 edges, 1 debt).

**The limits touched.** `_key_in_environment` (the runtime's key around a run, written into `core.ENV_INJECTED`) and `_budget` (the spend limit of a run) are principle 11 code and moved verbatim; the PR carries the verbatim diff of both, which is empty.

**Budgets and rows.** `OPS_PY_BUDGET` 2,687 to 2,531 (headroom 32 as before); `LAZY_CALLS_BUDGET` 64, `LAZY_EDGES_BUDGET` 52, `PLAIN_DEBT_BUDGET` 1; the rows of `ops_ask`, `ops_cancel`, `ops_contained`, `ops_file_ask` and `ops_research` to `ops` are gone; the dispatcher's row becomes `CYCLE_ENTRY` (OPEN-C4: `bootstrap` returns the module to the scheduled job and calls no function of it); `ops_runs` gains `ops_ask` in its cycle row. `test_operations_table.py` no longer lists `task_prompt` and `code_task` in `NOT_OPERATIONS` (they are defined in `ops_runs`, which is not a public module of the table); `test_runtime_rules.py` allows `ops_contained.py` the top-level imports `ops_models` and `ops_runs`.

**Alternatives rejected.** Leaving the helpers in `ops.py` and calling them through a seam (that is C2, for the operations of the table only; these are private helpers, which move). Moving `_route` (it only returns `ops_models.route(...)`, so the siblings call that directly). Moving the run body in the same package (C4, OPEN-C2: after the launch, in two modules).

**Not changed.** No rule, phrase, policy or approval; the entry golden is untouched and replays identically; `dir(ops)` is the same set of names.

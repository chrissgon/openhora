## 2026-10-28: T8-0b and T8-1: the phrase snapshot, and the messaging and phone tests assert phrase keys (T8-1; SPEC-V3-STRUCTURE section 5; tests only; no model call, no provider call, no lab run, fingerprint unchanged)

Two pieces of T8 in one pull request, as the spec's order says ("the snapshot comes with the first conversion piece").

- **T8-0b, the snapshot.** `runtime/tests/phrase_snapshot.py --write|--check` renders every key of each language (1,031 keys in each, the phrase parts included) with fixed fictional field values, one line `KEY: sentence` per key, sorted, into `runtime/tests/snapshots/phrases.en.txt` and `phrases.pt-BR.txt` (a newline in a sentence is written `\n`). A field takes the value `VALUES` gives its name; a field that has none renders as `<name>`, so a renamed field shows in the diff. `runtime/tests/test_phrase_snapshot.py` runs `--check` and prints the `--write` command when the table and the files differ; a conflict in a snapshot file is resolved by running `--write` on the rebased tree, never by hand (OPEN-S10). The pt-BR file is Portuguese by design, so `.security-scan-allow` names it for `english-only` (one named file, no folder glob; the part files of the table are exempt by rule, this one is generated data). `scripts/select_tests.py` adds `test_phrase_snapshot*` to the tests a change to a phrase file selects (the `phrases_*` row), so a pull request that changes a sentence or adds a part runs the check in CI as well as locally.
- **T8-1, the conversion.** In the messaging and phone family (`test_messaging_*` except the natural-layer files and `test_messaging_attach.py`, which T8-4 owns; `test_phone_*`; `test_channel_grants_*`) a literal that quoted a table sentence became `pk.said` or `pk.assert_said` with the key and the fields the test meant (a count, an id, a title, a date value). Where a sentence ends with the place (`{where}`), `runtime/tests/phone_said.py` (new, a test kit with its own `test_phone_said.py`) adds `placed` (the sentence of the key, and its place being the table's page and a full stop, or the page link), `refused` (the plain refusal) and `alone` (that sentence and nothing else); without it every test would quote a second table sentence (PHONE_WHERE). No test was removed or merged; the shared literal file `phone_literals.py` is left as it is (about forty test files of other families import it), and the files of the other T8 pieces (calendar, mail, files, `test_messaging_attach.py`, the natural layer) are untouched.
- **Counts.** The spec's heuristic (a fixed fragment of 14 or more characters of a template inside an assert) finds 137 asserts in these 44 files; 122 became keys and 15 stay (below). Beyond the heuristic the conversion also took the sentences it does not see (a constant a test compares with, a tuple a loop iterates, a sentence shorter than 14 characters, a card line, a nested place or a service name), 314 lines of assert or loop in all now name a key. 12 literals carry `# literal: <limit>`.
- **Kept literal, and why.** (a) A text that is not a table sentence: the `OpsError` words a terminal prints (`an effect is approved in the terminal, with its hash`, `as the whole line`), the page's own text from the interface, a fixture a stand-in returns or a planted old line an oracle must flag, a person's own text a card shows whole. (b) The spec's limits: a phone card shows no raw event id, snapshot name or version (`TECHNICAL` and the internals asserts of the calendar and mail cards); the stop word the research acknowledgement shows is in the closed list (`test_messaging_research_brake.py`); the old digest and old help words a phone must not show; an operations-layer text an English phone is told as it is. (c) A kit limit: the body of a draft card is a field of several lines, which the kit cannot match inside a longer card, so its first line is kept literal (`test_channel_grants_mailbox.py`); a held-task line the network cut is no longer the whole sentence (`test_phone_command_sentences.py`).
- **Vacuity.** Sampled, on tests of six files, with the production code or the table changed for one run and restored: a key switched in production (`ops_natural` `accept-config` to `PHONE_SOURCES`; `messaging_bridge` `WORD_ONE_AT_A_TIME` to `CHANGED`) failed `test_phone_guard.py` and `test_messaging_card_words.py`; a field changed (the count of `CMD_ATTACHMENTS` off by one; the id of `NT_SET_TEXT` off by one) failed `test_phone_command_sentences.py` (5 cases) and `test_messaging_reminders.py` (3 tests); three sentences reworded in `phrases.py` and one in `phrases_pt_br.py` left 128 converted tests green and failed `test_phrase_snapshot.py` with the four changed lines. `test_phone_said.py` has its own planted-wrong cases (another key, another place, a missing stop, the other language, a caption before the sentence).
- **Spec facts that moved.** The table has 1,031 keys in each language (the spec said 894: the catalog batch and the parts added the rest). The spec's heuristic finds assert-level quotes only; loops over literal tuples and constants (`TECHNICAL`, `ERRORS`, `CASES`, `LEAD`) are missed, which is why the conversion went beyond its count.

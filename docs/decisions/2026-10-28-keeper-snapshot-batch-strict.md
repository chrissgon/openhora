## 2026-10-28: the phrase snapshot is strict on a batch and lenient on a package, as the generated blocks are (BATCH-KEEPER snapshot-batch-strict; no model call, no lab run, fingerprint unchanged)

**Why.** T8-0b (#642) added `runtime/tests/snapshots/phrases.en.txt` and `phrases.pt-BR.txt`, one sorted line per phrase key, checked byte for byte by `runtime/tests/test_phrase_snapshot.py`. Every package that adds or rewords a key had to regenerate them, and in a sorted file the new keys of two open packages sit next to each other and conflict: the hot spot HOT-1 removed for the generated blocks of `docs/architecture/platform/` (`docs/decisions/2026-10-28-hot-1-ledgers-and-batch-blocks.md`).

**Change.** The test reads `WB_GENERATED_BLOCKS`, the variable of the blocks (set by `.github/workflows/checks.yml` and `nightly.yml`):
- `strict` (a batch pull request, a pull request into main, a push to main, the nightly run): `phrase_snapshot.differences`, the files equal the table byte for byte, as before.
- anything else, the default when it is unset (a package's pull request into the integration branch, a local run): `phrase_snapshot.lenient_problems`. It fails only for what a package cannot leave stale: a snapshot file that does not exist, a key of a snapshot file that the table does not have, and a key of the table whose sentence cannot be rendered (an invalid field or format). A reworded sentence, an added key and a key missing from the snapshot pass.
`phrase_snapshot.problems(mode)` chooses between them; `--write` and `--check` of the script are unchanged (`--check` stays strict).

**The batch regenerates it.** The batch keeper's regeneration pull request (a `batch/...` branch) runs `python3 scripts/architecture_tables.py --write` and `python3 runtime/tests/phrase_snapshot.py --write` in the same commit, and its strict run checks both. A package never regenerates either, and a conflict in a snapshot file on a package's branch cannot arise, since the package does not touch the files.

**Tests** (`runtime/tests/test_phrase_snapshot.py`, 6 new, with the table of that file and its own literals): strict fails on a reworded sentence and lenient passes it; lenient passes an added key and strict does not; lenient still fails for a snapshot key the table lacks, a missing file and an invalid sentence; an unset or unknown mode is lenient; a vacuity case where the lenient check is replaced by the byte comparison and the planted reword fails; and the real table is clean in both modes on this tree.

**Principle 13.** Saved: no per-package snapshot regeneration and no conflict on the two sorted files. Given up: on a package's pull request a reworded sentence is no longer shown in the diff of the snapshot and a test that quotes nothing no longer fails for it; the review sees the change in the table's own diff, and the batch's diff of the two files shows every reworded sentence with its values in place before the strict run on the batch passes. A wording change that no batch ever regenerates fails the nightly.

## 2026-10-28: a negated noun does not choose the kind of a list (ITEMS-NEGATION; OPEN-1 accepted as recommended, 2026-10-27)

The live case (2026-10-26, BL7-1 report): "mostra minha agenda" -> "Posso?" -> "I meant my unread emails, not the calendar". `natural_writes.items_noun` and `items_kind` read a line that names both nouns as the calendar, so the corrected plan equalled the old one and `ops_interpret` dropped it (`PLAN_DROPPED`): safe, nothing ran, but the person got no new "Posso?". The BL7-1 test that pinned this ("the plan is dropped") is now the test that pins the new question.

- **Tables.** A new top-level list of `requests.writes`, `negators` (phrases, the shape of `polite` and `articles`), in `TOP_KEYS` so `check_writes` checks its shape. en: not, never, without, except, instead of, rather than. pt-BR: nao, nem, sem, exceto, em vez de / do / da, ao inves de / do / da. Not `no` (the lists merge across tables and the pt-BR "no" is "in the": "eventos no calendario") and not `menos` ("pelo menos a agenda"); a test pins both. As for every list of `writes`, a table without the key reads as an empty list (the key is checked when present, never required).
- **The reach.** `natural_writes._nouns_named(line, phrases, tables) -> (plain, negated)`: a hit is negated when the folded text right before it is a negator phrase followed only by single spaces and article phrases (`articles`), with no mark in between (the helper is named `_nouns_named`, not `_named` as the spec says: `_named` is a function of the value oracle that moved to `turn_gate`, and `test_turn_gate_provenance` requires the old home to hold no function of that name): "not the calendar" and "nao a agenda" are negated; "nao, a agenda" (a comma), "no calendario" and "not the unread calendar" (a word that is no article) are not.
- **The readings.** `items_noun`: calendar when a calendar noun is plain; else mail when a mail noun is plain; else the other kind when only one kind is negated ("not the calendar" is mail, OPEN-1: items lists only mail and calendar, and the person said which not to show); else None (nothing named, or both negated). `items_kind`: calendar when a calendar noun is plain, or when the only mail nouns are negated and no calendar noun is named; else mail. A line with no negator reads as before (both nouns named and none negated is still calendar).
- **What did not change.** The kind of the old plan is still kept when the new line names none (`ops_items.items_args`); reads only, always behind "Posso?" (confirm-reads on by default): a wrong kind costs one more "no", never an effect. No card, approval, credential or outbound data. 0 model calls; the entry golden is not re-recorded.
- **Left alone.** "not the calendar nor the emails" has no negator in the closed list for "nor": the e-mails are plain, so it reads as mail. A negator list for the other languages the interpreter reads (es, fr, de, it) waits for those tables.
- **For S41-11.** `items_kind`, `items_noun`, `_nouns_named` and `negators` serve the interpreter path (`ops_items.items_args`, `plan_confirm`) and move with them if `natural_writes.py` is cut down.
- **Principle 13.** Saved: the correction after a "Posso?" gets its new question instead of a dropped plan. Safety given up: none that a hard limit holds; a line that negates in a way the closed list does not know ("nor") still reads as before.

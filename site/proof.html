Proof decides the model and the autonomy

In openhora, recorded test evidence, not a person's opinion, decides which model runs a skill and what may happen without a person.

⊘ What this does not guarantee

  • "Every skill is verified correct" or "tested to 100%".
  • "Works on any model."
  • "The AI decides what it may do."
  • A bare number ("98%") with no model, date, run count and band beside it.

The pessimistic score, exactly

With S the sum of scores and N the number of runs, p = S / N and z = 1.2816: (p + z²/2N − z·√(p(1−p)/N + z²/4N²)) / (1 + z²/N), 0 when N is 0. evals/eval_status.py, pessimistic_score. Under 0.70 the band is watch.

Starting values: biz-icp-positioning's published gate, 1.00 vs 0.40, 9 runs. Not simulated here: guard assertions, version changes and field evidence.

02/ 07

Approval of the exact content before any side effect

Anything that changes the outside world (a post, a pull request, a commit) is shown to the person as exact content with its hash, and runs only after the person approves that hash.

⊘ The safer wording

  • in the runtime, code executes effects only under an approval of the exact content or inside an approved policy; run by hand, the protection is a measured guard, not a lock.

Verify on main

terminalrepository root
$ python3 evals/eval_status.py status# guard assertions: 256 tagged guard or guard:<effect> (snapshot 2026-10-10)
  • ▦contracts/environment.mdthe side-effect vocabulary, and the rule that an approval binds a hash of the payload
  • ▦contracts/runtime.mdlimits L6, L14 to L17; the four contained-run restrictions R1 to R4

03/ 07

A harness-agnostic core, with adapters

The skills do not belong to one AI tool. Everything specific to a tool lives in an adapter folder; adding a tool does not edit the core.

⊘ What this does not guarantee

  • "Works with every AI tool."
  • "Fully tested on every tool listed."

Verify on main

terminalrepository root
$ ls adapters/agents-dirapiclaude-code
terminalrepository root
$ python3 scripts/validate.py# fails if a core file names a harness
  • ▦AGENTS.mdthe rules: a harness-agnostic core; open-closed adapters
  • ▤adaptersone folder per AI tool, each with a README

04/ 07

Artifacts over invocation

What a step produces is a file in your project that the next step, another skill and a person can read.

⊘ What this does not guarantee

  • "No state is kept."
  • "Skills are independent" (they depend on each other's artifacts).
  • "Works with any folder layout" (the layout is a contract: contracts/project-layout.md).

07/ 07

The person can always take power away

From the page, a person can stop an agent or lower its mode at once; widening what an agent may do is done only in the terminal.

⊘ What this does not guarantee

  • That the MCP or chat channel can approve an effect: by design they cannot.

Verify on main

terminalrepository root
$ python3 runtime/cli.py set-mode --project <dir> --agent <name> --mode stopped# a move down: code accepts the new hash at once (code:narrowing)
terminalrepository root
$ python3 runtime/cli.py accept-config --project <dir> --sha256 <hash># a move up: accepted only here, in the terminal
  • ▦contracts/runtime.mda change that can only take power away is accepted at once from any channel; widening is not
  • ▦interface/README.md“a page can never accept the change that widens what an agent may do”
  • ▦runtime/README.mdthe MCP mode has no tool for approve, reject, cancel, retry, accept-config, run-next
